# 工程团队试用指南

CFD-Paper-Agent把已经算好的结果连接到分析、图件和论文草稿。工程人员可以把已有导出表、
方法说明、配置、定义脚本和参考文献交给本地AI，让它读取资料、提出科学问题并组织论证；
不必先由人把全部信息手写成JSON。软件负责明确计算、数值引用和文档组装，宿主AI负责
科学理解和学术表达，作者决定研究方向与最终稿。

## 本版适合怎样的试用

先选一个结果完整、变量定义清楚、至少有匹配对比的真实项目。传热、流动、燃烧或电池
热问题均可；研究对象不是产品限制。已有结果可以来自任意求解器，但本版直接使用CSV、
显式映射的NPZ、文字方法及配置记录。原生`.sim`或`.cas/.dat`中的必要字段应先用已有工具
导出，不把本版说成能够自动读取任意求解器模型。无需新求解或参数拟合。

给AI三个基本信息即可开始：资料所在目录、本轮想形成的小节或论文范围、哪些资料允许
使用或对外分享。科学问题不必已写好，AI可先从材料提出可辩护的比较。缺口只在影响
主张时询问，不能反过来要求工程人员替它完成全部模型和证据梳理。

## 安装与最短上手路径

使用Python 3.10–3.12，在下载的仓库根目录安装：

```powershell
python -m pip install ".[docs]"
cfdpaper --help
python examples/effective-methods/run_example.py output-effective-methods
```

教学例子是自造记录，仅用于熟悉操作。它展示定义读取、两列时序差值、两面板图、原生
表格和公式、四节Word及可搬迁续写；不代表真实模型验证或AI科学写作质量。

把以下请求交给可读取本地文件和运行Python的宿主AI，并替换目录和交付范围：

> 请使用已安装的CFD-Paper-Agent及其cfd-paper-workflow、分析、制图和写作技能，读取
> STUDY目录内已有结果。先识别工况、有效模型/边界、报告算子、可比性和重要缺口，提出
> 2–4个有证据支持的问题供我选择；不要让我先转写全部JSON。确认方向后，用现有API
> 形成数据分析、可编辑图件和连贯的Methods–Results–Discussion小节，导出Word并检查
> 实际页面。保持原始结果不变，不运行求解器或拟合。优先解释相互支持或相互矛盾的
> 观测，避免把正确计算、守恒或匹配单点称为物理验证。缺失数据具体说明，继续有证据
> 支持的工作。最终给我可编辑文件、关键来源及需要我补充的最少事项。

## v0.20的具体改进

方法定义不必再从文件开头猜测。先定位符号，再读取选定定义：

```powershell
cfdpaper inspect STUDY --materials --material-path model.py --output method-index
cfdpaper inspect STUDY --materials --material-path model.py --definition Model.balance --output method-body
```

定义文本保留原始行号和截断提示；AI仍应沿实际调用与配置判断哪套模型生效。原项目
Python只作为文本读取，不被导入或运行。

同一保存记录的两列可声明`temporal_difference`，计算comparison−reference。它保留时间、
两原值、差值与原始位置，使用精确保存窗口、非均匀梯形积分和保存样本阈值定义。温差
用K；它不是热流、原生事件或自动因果证明。正文统计与profile图使用同一声明，避免
手算差值后在不同文件里重复维护。

少量文献可以在已有literature evidence中附`citation_record`，让出版书目与支持论断分开。
已有共享CSL文献库仍适合整稿；软件不猜作者、标题、年份或支持关系。大图可以显式设
`placement: "section-end"`，保留字体和尺寸，在节末插入；实际Word页面仍需检查，不能
承诺自动消除所有留白。

## 判断这次试用是否有价值

请看AI是否识别了真正有效的模型与条件，原始数值和单位是否正确，图是否展示了决定
论断的关系，Discussion是否解释了独立或相反观测，而非只列终值。Word还应有正常
首行缩进、段距、图注、书目、原生表格/公式和无明显分页硬伤。

把草稿、输入、图件及完整评阅一起保留。科学不足应改进证据选择、算法或技能，不能
仅手工修好一篇示例再宣称产品升级。不同宿主模型的效果仍需实际试用；本版没有证明
任意AI都能独立完成投稿级论文。需要共享问题时，只回传经批准的脱敏资料和具体错误。
