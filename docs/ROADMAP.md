## Current direction: Research Workbench

The author approved the [v0.21–v0.24 development plan](research/CFD_RESEARCH_WORKBENCH_UPGRADE.md).
The v0.21.0 increment connects supplied surface results, physical-area diagnostics,
complementary figures and a host-written research manuscript. A known four-case cooling
study exercised the chain, followed by a source-grounded conceptual figure and selective
refresh with author-asset preservation. The CLI and a runnable public synthetic example
expose the same workflow; see the [release notes](releases/v0.21.0.md) and
[surface tutorial](../examples/surface-research/README.md).
The v0.22 release extends this chain with original-field regions, signed heat paths,
matched changes, budgets and an actual saved-Fluent surface reader. A real cooling task,
paired first writing, temporal-support counterexamples and author-preserving refresh have
run. Platform checks and published assets are linked from the [v0.22 notes](releases/v0.22.0.md).
The v0.23 increment adds ordered scientific document views, formal profiles and managed Word
author return. A real cooling manuscript exercised actual author wording/caption edits and a
comment, followed by product recovery and host caption revision; native Word pages and an
IEEEtran-based LaTeX output were inspected. A portable public analytical replay is available in
the [author tutorial](../examples/author-collaboration/README.md). Release validation and exact
boundaries are recorded in the [v0.23 notes](releases/v0.23.0.md).
Existing releases and their limitations are retained below as history.

Each release must improve an actual research task. Later task ordering can change with observed
results, but scientific depth, readable publication output and author-edit preservation cannot be
silently removed. The [contribution principles](../CONTRIBUTING.md#product-and-development-principles)
apply across hosts and contributors. No universal solver support or publication readiness is implied.

The [Workbench plan](research/CFD_RESEARCH_WORKBENCH_UPGRADE.md), section15, records the v0.22
assessment and the v0.23 implementation sequence. The actual author cycle is now exercised:
generated Word wording and caption edits return against their baseline, supported edits can
coexist with current source values, and unresolved comments and conflicts remain located.
The host remains responsible for changed scientific meaning. Existing diagnostics, native
extraction and first drafts are retained, not regenerated. Arbitrary Word round-tripping,
solver expansion, second-host evaluation and automatic submission are not part of this increment.

## Release principle

The repository is published early and improved in visible, evidence-backed increments. A public
version contains only capabilities that run and are tested at that tag. Longer-term targets remain
recorded here instead of being represented as already complete.

## Delivered v0.10 direction

The v0.10 increment is defined in the
[v0.10 scientific-writing plan](research/V0_10_SCIENTIFIC_WRITING_PLAN.md): explicit spatial
weighting connected to diagnostic selection, substantive host writing, complementary figures
and actual Word presentation. Weighted mean, population SD and measure sum now bind to prose and
Word tables, including the distinction between absolute-temperature and temperature-difference
units. Host skills connect field extent and location with summary diagnostics; numeric table
headers now follow their columns' alignment.

The [public spatial example](../examples/spatial-diagnostics/README.md) carries analytical source
facets, editable four-format artwork and a recorded guided host draft through relocation and Word
export. Local transfer and rendered-page checks are documented in the plan; supported-platform
CI results accompany the release commit. Recorded replay is not a new model
invocation, an unfamiliar-project writing benchmark or physical validation. See the
[v0.10.0 notes](releases/v0.10.0.md) for the bounded release scope.

Development follows the path from mature CFD results to an author-approved scientific paper:

1. solver-neutral and solver-assisted result intake;
2. scientific comparison, QoI, trend, uncertainty, and field analysis;
3. publication figures and linked scientific writing;
4. full paper structure and document export;
5. pre-submission review and event-driven revision after real reviewer comments;
6. heterogeneous validation across flow, heat-transfer, and multiphase projects.

Further releases will narrow this list to one primary user bottleneck before implementation. This
keeps each public increment useful and testable without presenting the long-term system as already
complete.

## Long-term maturity gates

| Gate | Deliverable | Promotion rule |
|---|---|---|
| 0 | Product contract, isolated repository, legacy boundary | Public interfaces frozen and no private assets tracked |
| 1 | Installable CLI and resumable project | New project initializes and resumes offline |
| 2 | SQLite/FTS hybrid retrieval and context packets | Fresh evidence is retrieved; stale evidence is excluded |
| 3 | Scientific core and reference adapters | Known private-regression scientific failures are blocked |
| 4 | Analysis, figures, writing and export | Claims remain evidence-linked and artifacts are real |
| 5 | Pre-submission review and event-driven revision | No planned or synthetic change is reported as complete |
| 6 | Three heterogeneous real-project validations | Zero hard scientific and cross-document errors |
| 7 | Stable public package | CI, docs, examples, license and release checks pass |

These maturity gates describe the route to a broadly reusable product. They do not imply that the
current release already supports arbitrary solver files, complete manuscripts, or unattended
research decisions.
