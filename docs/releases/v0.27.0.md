# v0.27.0 — Evidence-grounded mechanism continuation

This increment connects a current physical question, selected observations and method definitions
to host-authored mechanism artwork and scientific writing. It extends the existing research
workspace rather than adding a second reasoning or drawing platform.

## What changes in a research task

- `research_question_context(...)` and `research --question-context` recalculate selected evidence
  from the current sources. The reading view includes the owning calculation, physical definitions,
  bounded source excerpts and related passages and figure captions. It does not guess an answer
  from the question or copy the original field arrays into the host context.
- `research --attach-figure ... --replace-figure` (Python: `replace_existing=True`) imports a revised
  mechanism diagram under its existing exact ID. Its number and body paragraphs stay in place;
  previous editable sources remain alongside the new candidate. The new caption and inspection
  state accompany the artwork, while scientific wording remains an explicit host/author action.
- Initial figure attachment also extends an explicit author block order with a stable introduction
  paragraph and the new figure. No manual document-order repair is required for this workflow.
- Passage-level change context now covers regional `difference_mean` reversals. It distinguishes
  comparable sign changes from changes in support, operator, baseline, units or upstream definition;
  it does not automatically turn new numbers into new causal conclusions.

The bundled writing and figure Skills describe how to use these actions without replacing author
judgment or silently overwriting existing local drawing sources.

## Try the complete continuation

From the matching source checkout/archive with Word support installed:

```console
python examples/research-expression/run_example.py output/research-expression
python examples/mechanism-continuation/run_example.py output/research-expression output/mechanism
```

Open `output/mechanism/interpretation-updated/manuscript.docx` and compare its earlier candidate.
The example adds an editable original-face/observation-support schematic, changes an isolated
source copy so a mean difference moves from +2.250 K to −1.750 K, and locates the affected passages.
An explicitly supplied example-author revision updates the interpretation, diagram and caption
under the same figure identity. Earlier author sources, table inputs and plotting scripts remain.
This is constructed-data software continuation, not an additional CFD operating point or
independent physical validation. See the [example guide](../../examples/mechanism-continuation/README.md).

## Real-task use and scope

A known cooling task uses unchanged original-face temperatures, native interface budgets and
signed height-resolved conduction. Studio-guided editable artwork defines the actual source
footprints, layers and control volume without inventing channel topology. Its scientific revision
distinguishes retained copper-base spreading from the offset QDLJ upper-band inward exchange;
that arrow is solid conduction, not coolant backflow. The four-section research unit connects
those definitions and complementary figures to the revised discussion and conclusion.

The interpretation remains specific to the supplied model: constant properties and omitted
buoyancy mean source relocation alone does not induce a different same-geometry flow. Lower
interface temperature does not by itself establish higher local convection or lateral export.
The known-project replay is not an unfamiliar-project scientific validation. General mechanism
quality still needs host/author assessment against actual figures and manuscript pages, and real
transient/multiphase CFD maturity remains open.

Release checks include the supported Windows/Linux Python 3.10–3.12 matrix and installed-wheel
example continuation. Actual release runs and distribution assets are available from the
