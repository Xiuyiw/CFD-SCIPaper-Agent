# v0.10.1 — Direct array analysis and readable numerical output

This update removes manual data-conversion work from the spatial-analysis path introduced
in v0.10.0 and fixes numerical typesetting in Word. Existing CSV proposals remain supported.

## Changes

- Large CSV files receive bounded previews and streaming row counts while their complete
  sources remain available for calculations.
- NPZ files expose key, shape and dtype metadata. Explicitly mapped, aligned one-dimensional
  arrays can feed the existing calculations directly; units are declared rather than inferred.
- Weighted statistics accept a supplied regional overlap fraction and its complement.
  Element area or volume is multiplied by that fraction. Plotting and tables use the same
  regional calculation, and source updates propagate to bound manuscript values.
- Word preserves the attachment of a numerical minus and recognized units to their numbers.

## Try the array example

From the matching checkout:

```text
python -m pip install ".[docs]"
python examples/spatial-diagnostics/run_array_example.py output/array-demo
cfdpaper write . --artifact results-section --package output/array-demo/section --docx --layout near-reference --output output/array-demo/array-demo.docx
```

The [tutorial](../../examples/spatial-diagnostics/README.md) includes hand-checkable answers
and relocation instructions. It replays a supplied proposal and paragraph using synthetic
element fields, without a model API call. The original field-map example remains available.

Regional fractions require a physical definition and an upstream overlap calculation.
This update does not infer intersections from mesh geometry or reconstruct unresolved
within-element variations. It improves data handling and calculation-to-document delivery;
scientific interpretation remains the responsibility of the host and author.
