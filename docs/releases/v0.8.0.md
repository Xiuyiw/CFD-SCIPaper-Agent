# v0.8.0 — Literature-linked manuscripts and source-aware updates

This version connects the manuscript workspace to shared literature and current owning evidence.
Authors and their host AI can develop chapter-specific arguments, keep summary values linked to
Results, and see which passages need attention when inputs change.

## What is new

- **Shared literature:** load local CSL JSON, or import BibLaTeX with optional Pandoc. DOI
  normalization and conservative bibliographic matching preserve shared identities and aliases
  across chapters. Conflicting metadata is reported rather than silently merged.
- **Claim-specific support:** each use of a reference carries its section, claim, role, exact
  source excerpt, locator and support decision. Only supported records enter citation evidence;
  withdrawn or deleted support cannot leave a stale citation in an assembled candidate.
- **Chapter-specific writing guidance:** Introduction and Discussion tasks connect literature
  to the study's question and interpretation. Abstract and Conclusions tasks summarize current
  results and scope. Keywords are included after the Abstract in Markdown and Word.
- **Direct evidence bindings:** summary sections consume evidence owned by another section.
  Declared calculations refresh from that owner's current CSV during assembly, including when
  the Abstract appears before Results. Values retain their units and source records.
- **Targeted change reports:** `CHANGES.md` and `changes.json` identify affected sections and
  paragraph positions after source, definition, literature, terminology or draft changes.
  Propagation follows explicit evidence bindings and `depends_on` links; unrelated drafts remain
  untouched.
- **Optional numeric CSL formatting:** a standalone local `citation_style` file travels with
  the workspace. Pandoc citeproc formats references in first-citation order, with one number per
  entry and bold/italic text preserved in Word.
- **Portable review material:** detached section review packets include relevant literature
  excerpts and source texts, plus owning definitions, calculation settings and small source
  tables for bound values.

## Try the seven-section example

Install a v0.8 checkout or matching wheel with the `docs` extra. From the checkout root:

```text
python -m pip install ".[docs]"
python examples/literature-manuscript/prepare_example.py my-source
cfdpaper write my-source --artifact manuscript --manuscript-input my-source/manuscript-input.json --output my-package
cfdpaper write my-source --artifact manuscript --package my-package --draft my-source/drafts.json --output my-manuscript
cfdpaper write my-source --artifact manuscript --package my-manuscript --docx --layout near-reference --output my-manuscript.docx
```

Every output path must be new. The [tutorial](../../examples/literature-manuscript/README.md)
contains Abstract, Introduction, Methods, two Results sections, Discussion and Conclusions.
It also walks through moving the assembled workspace and changing an owner source to observe
propagation. Its data and authored drafts are an analytical software example, not a new CFD study.
For original prose, use the prepared host tasks with your own evidence.

Pandoc is optional: the default metadata-label bibliography and the tutorial run without it.
For BibLaTeX import or CSL formatting, install [Pandoc](https://pandoc.org/installing.html)
separately and make it available on PATH. Set `"citation_style": "my-journal.csl"` in the
manuscript manifest to select a local standalone style. PDF preview requires an existing
LibreOffice installation.

## Scope and compatibility

The existing evidence, subsection and manuscript routes remain available. The v0.7.0 wheel does
not include these additions; use the same compatible version when continuing a moved workspace.
Original local-ID drafts are retained. Word-only edits must be reconciled into those drafts
before re-exporting.

Binding values and citation numbers can update automatically; scientific interpretations and
figures do not. The change report gives the host a focused reading list rather than performing
full-text semantic revision. Excerpt matching confirms the supplied passage's location, while
the author and host assess its relevance and support.

CSL support is limited to bracketed numeric citations in first-citation order with a leading
numeric bibliography label. Author–date, superscript, reordered numbering and unsupported
formatting produce an error. Dependent styles require their standalone parent file locally.
Neither bibliography route creates Zotero fields or invents missing publication metadata.

The release's public analytical example and known-case writing trials exercise this workflow;
they do not establish original full-paper reasoning on unfamiliar CFD projects. Native solver
extraction, automatic scientific interpretation and journal submission are outside this release.
See [Limitations](../limitations.md) for the full boundary.
