# v0.14.0 — From selected evidence to a first manuscript

This release makes it easier for a host AI to turn existing, selected CFD analyses into a
portable manuscript workspace. It also incorporates lessons from a complete cooling-project
writing trial. Scientific interpretation and prose remain host/author work.

## What changes

- **Collect selected inputs with `--outline`.** Use the existing manuscript input format with
  an optional `draft` path for each section. Absolute or outline-relative paths are accepted;
  declared data, figure and literature dependencies are copied while local evidence IDs and
  numerical bindings are preserved. Missing drafts are listed as pending, not filled with prose.
- **Guide the first whole-paper argument.** The workflow skill connects the research question,
  distinct section duties and complementary observations. The physics skill adds practical
  guidance for regional contributions, mechanism-bearing model controls and small ranking changes.
- **Typeset heat-flux units.** Recognized labels such as `W/m2` render as `W m⁻²`, including
  supported scaled prefixes, without changing the numerical value or the stored source unit.
- **Keep the declared publication source visible.** Default reference labels retain `publisher`
  metadata, including an explicitly supplied preprint designation. This does not verify metadata
  or replace optional journal-specific CSL formatting.

The bridge reuses existing calculations, manuscript assembly, shared literature and DOCX export;
it is not a new automatic research or solver-extraction engine.

## Try it

From the v0.14.0 checkout, using CPython 3.10–3.12:

```text
python -m pip install ".[docs]"
python examples/material-analysis/prepare_manuscript.py my-first-manuscript
```

Open `my-first-manuscript/manuscript.docx`. This public synthetic example uses recorded
Methods/Results prose, six computed bindings, a native table and editable mathematics.
It demonstrates the interface, not autonomous paper writing.

For selected inputs from your own analysis tasks:

```text
cfdpaper write STUDY --artifact manuscript --outline outline.json --output workspace
```

The workspace's `TASK.md`, `drafts.json` and `drafts-template.json` identify the supplied and
unfinished sections. Complete the missing drafts, then use the ordinary assembly and continuation
commands in the [tutorial](../../examples/material-analysis/MANUSCRIPT.md).

## What the real trial established

A host working in a separate context produced a complete nine-page first draft from selected
existing cooling materials, with five figures, three tables and native equations. A concentrated
fresh-context review found the principal numerical comparisons sound, but incomplete method
reporting, underused mechanism evidence and overstrong interpretation of small differences.
One feedback-assisted revision integrated existing temperature-drop, regional heat-path and
matched-model evidence. The revised ten-page document was rendered and inspected; relocation
and fresh-process reassembly preserved its text, numbering and Word body/style XML.

This demonstrates a workable first-manuscript and revision workflow. It does not demonstrate
independent scientific validation, submission readiness or general improvement in first-draft
reasoning. The host still prepared the analysis mappings, figures and prose; missing geometry,
near-wall, uncertainty and literature evidence remained missing. Private research materials and
manuscripts are not included in the public distribution.

## Continuing older drafts

Preserve the original candidate and any Word edits. Changed display rules can make an older
review snapshot fail the current reassembly check. Reassemble a working copy before making a
new review package, or continue explicitly from an ordinary copy; do not silently retarget an
old review to changed text. The original snapshot remains available for comparison.

See [limitations](../limitations.md) for unsupported native solver ingestion, automatic scientific
validation and other remaining scope boundaries.
