# v0.13.0 — Host-assisted materials-to-manuscript workflow

This update reduces handoffs between ordinary research materials, supported calculations and
an editable manuscript. The host AI interprets the evidence and writes the scientific argument;
CFD-Paper-Agent profiles inputs, computes declared quantities and maintains source-bound values.

## What changes

- **Definition scripts become readable materials.** `.py` files are included as line-numbered
  source text, so the host can recover quantity definitions and method settings. Intake does not
  execute these scripts.
- **One entry connects existing skills.** `cfd-paper-workflow` routes the host to evidence intake,
  QoI/physics, figure production and evidence writing as needed. Analysis packages include the
  entry, all four specialist skills and their references, so the guidance travels with the materials.
- **Calculated Results feed the manuscript directly.** A public two-section example connects the
  generated Results input to Methods without rebuilding its six `result_ref` bindings. It uses
  existing manuscript assembly, native editable math, tables and Word export.
- **Actionable claim-ID errors.** Unknown `required_claim_ids` identify the problem and explain
  local evidence IDs and `evidence_bindings` aliases. IDs are not silently rewritten.
- **Calculation gaps and interpretation limits stay distinct.** Host guidance places unresolved
  definitions that block the selected comparison in `missing_questions`, and evidence needed only
  for stronger explanations in `interpretation_limits`. Calculation checks are unchanged.

Multi-section manuscripts, numerical source updates, current writing context and Word export
already existed. This update makes those capabilities easier for a host to connect and reuse.

## Try the public example

Use CPython 3.10–3.12. From the v0.13.0 checkout root, install with Word support and run:

```text
python -m pip install ".[docs]"
python examples/material-analysis/prepare_manuscript.py my-material-manuscript
```

The output directory must not already exist. Open `my-material-manuscript/manuscript.docx` for
the Methods/Results document with native inline math and a native table. Its `manuscript/`
directory contains the portable candidate; `workspace/` contains the prepared input snapshot,
and `analysis/` preserves the original analysis replay.

The example uses public synthetic data and recorded drafts, with no model call or solver run.
Follow the [bridge tutorial](../../examples/material-analysis/MANUSCRIPT.md) for details and
source-update checks. For a new host-authored task, start with the
[material-analysis tutorial](../../examples/material-analysis/README.md), then reuse the generated
`selected/section-input/writing/input.json` in the manuscript manifest.

## Continue an existing manuscript

Start from the candidate's `CONTINUE.md` and portable `drafts.json`. Preserve the current candidate,
edit a working copy and assemble to a fresh directory. Keep exact local claim IDs; use explicit
aliases when another section consumes the evidence. Source changes recompute bound numbers,
while the host rereads dependent scientific claims and explicitly exports the updated DOCX.

## Scope

Known-project use demonstrated practical material intake, reuse of existing bindings and targeted
manuscript continuation. It has not established superior scientific depth in independent first
drafts or generalization to unfamiliar projects. A fully automatic first complete manuscript from
an ordinary directory is not the demonstrated workflow. See [limitations](../limitations.md) for
the broader supported scope.
