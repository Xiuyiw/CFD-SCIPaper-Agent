# v0.21.0 connected surface research workbench

This version connects existing surface results to reproducible analysis, complementary figures
and a host-written research manuscript. It also brings reviewed mechanism artwork into that same
workspace. The practical gain is less temporary analysis code, manual asset copying and repeated
manuscript mapping: calculations, plots, numerical writing and source-change context share one
declared study. The host and author still choose the argument and judge what the evidence supports.

## Implemented

- `research --study` prepares a portable workspace from two to four declared NPZ face fields,
  supplied physical areas and original polygon geometry. Area-weighted mean, spatial population
  SD and threshold-exceedance fractions retain the quantity, units, domain and time-support
  definitions. Physical areas are supplied, not inferred from projected polygons or face counts.
- Original-face maps use a common color scale and coordinate limits. Area-exceedance curves
  preserve the exact empirical steps, with explicit strict or inclusive threshold semantics.
  Both figures include source CSVs, a runnable local script, editable SVG/PDF and PNG/TIFF previews.
- `research --workspace` assembles Methods, Results, Discussion and Conclusions with source-bound
  values, a native Word table and the host's prose. Large source-index lists in writing context
  use exact pointers into retained full reports rather than duplicating every face index.
- `--baseline` connects source and definition changes to affected outputs and interpretation-review
  locations. Author-local plotting scripts and drafts are retained; unchanged recipes can be skipped.
  A single affected recipe may redraw its complementary figure bundle. New candidates are separate
  from earlier builds, and the host revises any interpretation invalidated by changed results.
- Existing schematic/hybrid figure tasks include paper-framework Studio guidance, using the
  installed skill or its bundled adapted reference. `research --attach-figure` adds imported
  artwork, captions and body references to a new author workspace with existing global numbering
  and Word placement. Default delivery requires editable sources; explicitly selected
  `raster_concept` is schematic-only and reports that no editable source is available.
- Definition-only changes now identify affected mechanism figures and captions even when scalar
  results are unchanged. Conceptual arrows are flagged for host review, not automatically redrawn.
- The default surface renderer fits shared colorbars to fixed-aspect maps and removes unused
  vertical canvas space without changing the declared width, fonts or numerical coordinates.
  Existing author-local scripts are not replaced by the new default template.

## Install and try

Use CPython 3.10–3.12 and the matching v0.21.0 source checkout/archive. From its root:

```console
python -m pip install ".[docs]"
cfdpaper research --help
python examples/surface-research/run_example.py output/surface-demo
```

Alternatively, install a downloaded release wheel with Word support:

```console
python -m pip install "./cfd_paper_agent-0.21.0-py3-none-any.whl[docs]"
```

The example files are in the source distribution, not the wheel. Choose a fresh output directory
and open `output/surface-demo/candidate/manuscript.docx`. The
[public tutorial](../../examples/surface-research/README.md) generates six unequal rectangular
faces and two prescribed synthetic temperature fields, then replays supplied host prose through
the product APIs. It is a reproducible software example, not CFD or experimental validation and
not a new model-authored scientific result. No AI API or image-generation service is required.
Use `--prepare-only` for an empty host-writing workspace instead of the recorded prose.

For your own exported fields, follow the [study declaration and research commands](../research-workspace.md):

```console
cfdpaper research --study materials/study.json --output research-workspace
```

Read `TASK.md` and `RESEARCH.md`, inspect the calculations and figures, and fill the local section
drafts. Then build a candidate:

```console
cfdpaper research --workspace research-workspace --output build-01
```

For continuation, edit the latest candidate's `workspace/`, keeping the original inputs and
earlier candidates intact. Build to a fresh directory, for example:

```console
cfdpaper research --workspace build-01/workspace --baseline build-01 --output build-02
```

The [mechanism attachment guide](../research-workspace.md#add-a-mechanism-figure-without-rebuilding-the-quantitative-figures)
covers existing figure-task preparation/import, supporting evidence and paragraph placement.
Inspect actual figure previews and Word/PDF pages before accepting a candidate. Word-only edits
must be reconciled into the local drafts before rebuilding; automatic Word-edit merging is not
part of this release. PDF preview uses an existing LibreOffice installation.

## Demonstrated on an existing research task

A known cooling-project trial used four real saved surface fields with physical areas and native
face geometry. The connected workflow produced a four-section research draft with two quantitative
figures, a native table and numbered equations. A subsequent Studio trial added one concept figure
to Discussion and produced a five-page Word/PDF candidate; all rendered pages were inspected.
The original quantitative figures, numerical table and author plotting script were retained.

The scientific reading distinguished a change in mean temperature from changes in spatial spread
and area above a declared threshold. Both the preceding-version and candidate first writers found
that core observation. The demonstrated improvement is the connected workflow, not superior
scientific discovery or a measured percentage reduction in tokens or author time.

Separate source-value and threshold-change exercises refreshed figures, tables and bound values
while retaining author drafts and scripts. Those deliberately perturbed copies are software tests,
not additional CFD results. Preservation does not certify that old prose remains correct after
a changed trend; affected interpretations still need host review.

The added concept figure communicates source relocation, generic layered transport paths and
observed response directions. It is raster artwork, not an editable vector, a resolved channel
model, a heat-flux budget or independent mechanism evidence. Temperature fields alone cannot
separate conduction and coolant contributions. Source changes can therefore require revisiting
the arrows as well as the caption.

## Scope

This is a bounded surface-results route, not arbitrary native Fluent/STAR-CCM+ ingestion or a new
solver. It does not establish convergence, conservation, experimental validation, cross-model
generality or automatic SCI readiness. Research questions, comparability, literature support and
final scientific interpretation remain author/host decisions. The
[roadmap](../ROADMAP.md) retains deeper physical diagnostics, native extraction, limited Word
return and heterogeneous/second-host evaluation as later work. The
[v0.20.0 notes](v0.20.0.md) remain the preceding release record.
