# v0.16.0 — Scientific context for research writing

This release carries located method facts and literal source parameters into manuscript
writing, review and continued editing. The host can connect a result to its actual case,
solution stage and reporting operator without rebuilding those relationships for each section.

## Delivered capabilities

- An optional `scientific_context` file links cases, section-scoped facts, source excerpts
  and comparisons. Exact line ranges are checked; selected sources are copied into portable
  manuscript and section packages.
- Linked JSON records provide a readable parameter view with exact JSON Pointers. Material,
  boundary, geometry and solver fields appear first, with explicit truncation and parse issues.
  The host determines which records apply to a case; file proximity does not assign settings.
- Prepared and current section tasks include the relationships, source text and parameter view.
  Reassembly reports changed method facts and sources through the existing section dependencies,
  retaining the author's draft text. Whole-paper and standalone section reviews carry the records.
- The default bibliography displays an already-present DOI only once, including when its source
  uses a doi.org URL. Different DOI identities and meaningful non-DOI sources remain visible.
- `python -m cfdpaper` reaches the same CLI as `cfdpaper`, including outside the checkout.

The specialist skills use these records for concise reproducible Methods, distinctions between
local and total quantities, relevant numerical controls, and concrete comparisons with nearby
literature. Scientific interpretation and literature assessment remain host and author work.

## Observed writing results

A focused three-flow heat-transfer task compared an installed v0.15 first draft with a candidate
first draft in separate contexts. Both drafts preserved the principal values, units and reporting
domains. The baseline retained more geometry and boundary parameters; the candidate explained
solution increments and unknown monitoring definitions more clearly. Both needed a fuller
definition of a normalized percentage comparison. This task did not establish overall superiority
of the candidate.

The observed method omissions led to the literal JSON parameter view. One bounded candidate
revision used the updated product route and the supplied feedback; it remains feedback-assisted
host editing. The original first drafts and the complete independent report remain private.
The task is a held-out target within a known project, not unfamiliar-domain validation or an
independent research experiment. Actual Word pages are examined separately from software tests.

## Try it

With CPython 3.10–3.12 and the docs extra:

```text
python -m pip install ".[docs]"
python -m cfdpaper --help
python examples/material-analysis/run_scientific_context.py --output scientific-example
```

Use a fresh output directory. The example reuses invented wall-partition data, a recorded draft,
a native table and an editable equation. It demonstrates the product path, not new CFD research.
See [the scientific context guide](../scientific-context.md) for the input and portable reading views.

Native solver extraction, general transient/multiphase analysis, automatic recovery of arbitrary
Word edits and the original three-domain validation target remain future work.
