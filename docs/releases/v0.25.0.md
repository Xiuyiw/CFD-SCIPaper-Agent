# v0.25.0 — Connected scientific figures and report writing

This increment links report calculations, complementary scientific figures and host-written
Methods/Results/Discussion without a separate transcription step. It also adds a finite
original-field/diagnostic composition for inspecting where a signed transfer occurs.

## What changes in a research task

- Give `report_task` a `figure_plan` containing `panels`, optional `columns`, `style` and `caption`.
  A response panel selects a declared `x_calculation_id` and one or more calculated y series.
  Exact case identities join them; unlike units or missing case members are not silently combined.
  The same calculations supply the plot source rows, native table and bound manuscript values.
- Continue the report into a fresh directory after a source change. The retained author-local
  `plot.py` is copied and actually run against the new source rows. Draft wording is preserved;
  the host revisits explanations when the changed evidence requires it.
- Use `render_surface_composite` with two original-face fields and a selected layered signed-transfer
  diagnostic. The maps share a scale; explicit case IDs connect their positive, negative and net
  layer contributions. Optional region outlines identify declared physical bounds rather than
  invented contours. Original arrays are not interpolated or smoothed for analysis.
- Use the existing Studio drawing-task exchange for source-grounded editable mechanism artwork,
  including its caption and body reference. The cooling trial exercised that path with native
  vector art; this version does not add a general automatic mechanism-diagram engine.
- Dimensionless `1` remains the stored unit but is omitted from rendered prose values.

## Try the public example

Install the matching wheel with `[docs]`, copy `examples/bound-response-report` anywhere writable,
and choose a new output directory:

```console
python /path/to/bound-response-report/run_example.py /path/to/new-output
```

Open `new-output/candidate/manuscript.docx`. Its two response panels, native table and example
author prose use the same bound readings. The figure directory retains its source CSV, runnable
local script, SVG/PDF and PNG/TIFF. This example uses constructed values and supplied prose,
requires no model API or solver, and is not physical validation. See its
[README](../../examples/bound-response-report/README.md), the
[host/report guide](../portable-workbench.md) and the
[physical-diagnostics example](../../examples/physical-diagnostics/README.md).

## Evaluation scope

Known-project cooling tasks exercised separate interface-temperature statistics and section
pressure differences, plus original-face maps and height-resolved signed heat paths. Their support
definitions remain distinct: interface readings are not junction temperatures, endpoint pressure
differences are not automatically irreversible loss or pumping power, and reconstructed side-cut
heat transfer is not conservative native intercell flux. Field maps and path diagnostics from the
same solution are complementary observations, not independent validation.

P04's accepted field plots, data figures and schematics remain separate quality references at
manuscript size. This release does not guarantee that every new input will produce P04-level art
without host/author judgment. The host still chooses useful comparisons, inspects figures and
develops the scientific explanation. Synthetic examples and battery control-model regressions do
not fill the remaining mature real transient/multiphase CFD evaluation gap.

## Validation and publication evidence

The known-project report candidate was inspected in a two-page native Word/PDF output; the
connected field/diagnostic and editable schematic candidate was inspected across six pages.
A separate source-value perturbation exercised the current figure, table, prose and caption
bindings while preserving author drafts and the local script. This was a software regression,
not another simulated operating condition. Unit-changing continuations now require an explicitly
updated figure rather than retaining a misleading old axis label; assembled author captions
also supply the current writing context and figure summary.

Release requirements are the six Windows/Linux Python 3.10–3.12 test jobs and the isolated
installed-package smoke, including the public report example. The actual completed runs,
source commit and downloadable distributions are recorded in the
[v0.25.0 GitHub Release](https://github.com/Xiuyiw/CFD-SCIPaper-Agent/releases/tag/v0.25.0).
Passing these checks establishes the recorded software behavior, not general scientific validation.
