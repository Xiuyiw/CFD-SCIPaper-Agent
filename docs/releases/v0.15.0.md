# v0.15.0 — Scientific intake and manuscript continuation

This release makes existing evidence easier to locate and use, strengthens the host's scientific
writing guidance, and repairs a practical obstacle to continuing older manuscript reviews.
The host and author still develop the scientific argument; software keeps sources, calculations
and manuscript objects connected.

## New workflows

- **Find definitions beyond previews.** `inspect STUDY --materials --find TERM` searches readable
  source text and returns real file/line context. Repeat `--find` for literal OR matching and use
  `--material-path` to select files. A match locates text; it does not verify a physical definition.
- **Prepare a focused analysis.** `plan STUDY --artifact analysis --material-path FILE` passes
  explicitly chosen existing records into the analysis package. This avoids manually copying
  critical tables when a large directory exceeds default discovery limits.
- **Continue a review after display changes.** With an existing review/actions package, explicitly
  request `--refresh-display`. The original report and authoring materials remain unchanged; a new
  working copy maps old targets to the current display. Changes to sources, units, author drafts,
  numbering or scientific inputs are not accepted as display-only refreshes. The default still
  requires the original snapshot. See the [review tutorial](../../examples/literature-manuscript/README.md).
- **Carry the scientific guidance with the manuscript.** Prepared manuscripts and selected-section
  task contexts include the five workflow skills, rather than depending on the original checkout.

## Scientific and publication work

The existing skills now direct the host to read complete relevant categories, choose observations
that distinguish explanations, recover actual case-specific solution stages and report operators,
and compare the closest literature's findings rather than merely citing its background. Quantitative
adjectives retain the domain and comparison they describe; a layer's large change cannot silently
become a statement about the total. Source-assessment notes stay out of the bibliography.

At publication scale, the font check now uses hundredth-point comparison precision: an effectively
8.00-point label is not rejected solely because a declared image width differs by a tiny rounding
amount. The exact calculated size remains in the layout record; 7.99-point text still fails an
8-point minimum. This does not measure undeclared text or replace visual inspection.

## What the writing trial showed

Two isolated host runs used the same known cooling-project materials and task, one with the
released baseline and one with the candidate. First complete texts were preserved before feedback.
Both produced regional, layered and model-control arguments. The candidate organized some local
mechanism evidence more tightly and its final figures/tables were easier to read; the baseline
described some case and inlet details more completely. Both missed available solution-stage
information and underdeveloped the closest literature comparison. One candidate magnitude claim
also exceeded the scope of its supporting layer data.

These findings prompted focused writing-guidance changes. They do not demonstrate uniform or
general first-draft scientific improvement. The two ten-page Microsoft Word previews were inspected
page by page; successful assembly alone was not treated as publication quality. Feedback-assisted
editing is kept separate from the first-draft comparison.

The research example still needs its own physical validation and appropriate error estimates before
small differences support engineering recommendations. Native solver ingestion, arbitrary transient
or multiphase analysis, automatic Word-edit import and autonomous scientific validation remain
outside this increment. No private project materials are included in release distributions.

## Try the public example

From this checkout with CPython 3.10–3.12:

```text
python -m pip install ".[docs]"
cfdpaper inspect examples/material-analysis/inputs --materials --find area --material-path method.md --output matches
cfdpaper plan examples/material-analysis/inputs --artifact analysis --material-path regions.csv --material-path method.md --output focused-analysis
python examples/material-analysis/prepare_manuscript.py manuscript-example
```

Use fresh output paths. The example's prose is a recorded analytical demonstration, not new
research generated by the CLI. Supported-platform tests and installed-wheel replay are run in CI;
formal release assets are built from the successful main run.
