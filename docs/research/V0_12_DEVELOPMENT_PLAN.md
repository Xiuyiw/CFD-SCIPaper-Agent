# v0.12.0 开发计划：科学论证与可用成稿

2026-09-29。状态：作者已批准实施，科学入口与格式增量已接通，正在首次稿效果比较。
基线：已发布 v0.11.0，main `acf9691`。接续[后 v0.10 计划](POST_V010_DEVELOPMENT_PLAN.md)，
不重做已交付的比较计算、图件尺寸和单位修复。本文件同时承载实施进度，不另建平行审批文件。

## 1. 目标与真实基础

作者提供已有结果、方法资料、图件和初步研究意图后，宿主 AI 主动整理证据、提出分析、
写出相互支撑的小节，通过 Agent 交付可审阅整稿。作者不应先写好全部指标、解释和 JSON。

v0.11 改善了结果绑定、分析入口和单位排版，但已知项目的配对首次稿未证明科学深度系统性提高。
本版主目标是让“科学问题—互补诊断—机制解释—文献比较—结论”在实际写作中成立，
同时减少准备与修正负担。格式质量与科学内容共同验收，测试数量不是论文质量指标。

预期交付是一条可复用的宿主辅助写作路径，从材料准备到整稿组装；重点考察 2–3 个相关
Results/Discussion 小节及其与 Introduction、Methods、Abstract、Conclusions 的对应关系。
沿用整稿功能，不把只生成三个小节称为完成整篇论文。

### 执行方式

- 当前 `providers.py` 是配置占位接口，不是可调用多家模型的自动写作后端。
- 本版沿用 Codex 或其他宿主 AI 的工具调用：宿主读取材料、准备映射、提出分析、写作；
  Python 执行计算、数值绑定、引用编号和文档生成。不新建多模型平台。
- 优先改善现有任务包、相关上下文和内置技能的实际衔接，不只追加原则性提示词。
- 信息缺失先定位现有文件；只有会改变解释的缺口才问作者。缺少新仿真/实验/文献证据时，
  不能用语言补足，也不阻止独立可完成的软件工作。

## 2. 范围

保持 55% 科学理解分析、25% 绘图写作、10% 易用性、10% 必要可靠性的投入优先级，
不是代码行数配额。按 stop-that-shit，每项修改对应已观察障碍或本版必要交付。

本版不做：自动求解、通用原生求解器连接、任意几何交叠/插值、通用表达式引擎、模型微调、
文献平台、无限虚拟审稿、无损 Word 往返、投稿点击自动化、新注册表或批准体系。
不预先增加统计量；现有算子无法回答选定问题时，先说明最小缺口再决定是否扩展。

## 3. 工作包 A：科学问题与跨小节论证

复用 `publication/spine.py`、`manuscript.py`、`literature.py`、section context、
evidence bindings、现有任务文件及写作参考。先查信息没有进入推理的原因，再补最小连接。

1. 宿主从材料形成中心问题、比较设计、候选解释及判别所需证据；未知内容不推测填充。
2. 通过 `manuscript.py::_section_context` 及现有写作状态，给当前节提供相关图、
   计算结果/定义、依赖节当前段落、方法边界和有位置的文献支持。不塞入全量历史。
   初次写作尚无依赖稿时明确缺项，按依赖次序续写；修改后刷新相关上下文，不混入旧稿。
3. 先辨认场分布/趋势，再用最少必要数值支持论点；冲突指标应检查统计域、分母及尺度差异。
   同一数值的差值与百分比不是两份独立机制证据。
4. 区分观察、可计算关系、机制解释；有必要时比较竞争性解释和能区分它们的缺失观测。
   不强迫每段机械列假说、反例和限制。
5. 文献有真实来源、定位、支持角色和适用差异；优先已核实资料，必要检索沿用外部工具。
   元数据/摘要相似不等于全文支持；缺少最近研究不能被写成已建立新颖性。
6. 以 Methods 和 Results/Discussion 的证据为基础回核引言问题，再写摘要结论；
   后者不能加入结果中未成立的强主张。正文不输出内部任务、校验和审计措辞。

交付：实际增强的任务上下文、内置技能/必要代码、可搬迁多节示例和真实首次稿。
结构测试验证信息正确到达宿主；科学质量由阅读实际文段评价，不宣称自动判断因果真伪。

## 4. 工作包 B：真实长表入口

定位 `materials.py`、`analysis_suggestions.py::_Calculation/_check_calculation`、
`publication/section.py::_TableCalculation`、`table_evidence.py::calculate_table`。
按 case、metric、unit 及已知定义精确选记录，直接供给已有 scalar/pair/比较计算。
优先显式等值筛选和单位列核对，不强制 pivot 或新建一般 ETL 框架。

- 宿主根据表头和方法准备映射；作者只确认有歧义的科学含义，不要求手填 JSON。
- 同名指标的不同统计域/单位不能混合；零匹配、重复配对、单位冲突明确报告，不能默认取首行。
- 不把重复观测自动平均；需要聚合时沿用有定义的算子。保留原行位置、精度、case ID 与单位。
- 输入变动沿已有重算路径传播；若确需派生视图，保持原文件和行定位，不维护手抄数值。

验收：公开混合单位长表经分析、正文、原生表格链运行，无临时转换脚本或编译后手改；
原行及计算答案准确，缺失/歧义可定位，搬迁及改源值后仍可重算。
不宣称自动识别物理定义或自动完成任意单位换算。

## 5. 工作包 C：数值表达与出版格式

定位 `publication/section.py::assemble_section/export_section_docx`、`table_evidence.py`、
`elements.py::add_table`、`style.py` 及实际整稿导出入口。

1. 为现有绑定增加必要的显式简洁显示：物理定义/基准可在相应句或表头集中交代，
   后续数值不反复展开长标签。来源记录和尺度不变，默认显示仍可用；
   离开定义范围不能留下含混裸数，不用全局字符串替换删除单位。
2. 修正可复现的图注/图件/表格分页问题，优先检查 keep-with-next/keep-together 等具体原因。
   提供有限放置/跨页选项，保留图注所属和长表表头，不缩小全文字号、压缩图片或删文字消除空白。
3. 正文两字符首行缩进、段前段后 0 pt；标题/图注/表格不继承正文缩进。
   数字、单位、负指数、表头/数值对齐、最终图宽/字号须在实际导出中可读。
4. 图件服务论点，复用外部绘图接口及本地精修优先规则，不加重复面板或两点满幅图。
   手工修一张私有图或一份 PDF 不算公共能力提升。

验收使用固定正文和图件尺寸的修复前后页面：至少覆盖正文+图注跨页、长短表和公式/单位。
OOXML 检查配合实际 Word/PDF 目检，不通过改写科学内容凑分页；只报告实际渲染引擎。

## 6. 顺序与分工

| 阶段 | 负责人 | 产出和完成条件 |
|---|---|---|
| M1 选择真实任务 | 主控 | 通过既有索引选择主写作任务和不同问题回归；说明输入与关键缺口，不扫描全档案 |
| M2 科学链与入口 | 支线 A，主控接共享接口 | A/B 通过公开入口运行；当前证据/邻节进入任务，长表不需临时接线 |
| M2 并行格式 | 支线 B | C 的可复现缺陷被公共修复，同文本实际页面更可读 |
| M3 首次整稿比较 | 独立上下文宿主，主控整合 | v0.11 与候选同输入首次稿保留，完成一次集中内容/格式评阅 |
| M4 定向修复 | 主控+A/B按需 | 确证缺陷进入产品和定向测试，区分初始与修复后表现，不无限重写示例 |
| M5 交付与发布准备 | 主控 | 文档/技能/公开例子同步，原有 CI 与隔离安装通过，按发布授权收口 |

批准实施后，普通阶段主控连续推进并汇报，不要求每步说“继续”；科学方向选择、
无法获得的关键证据、新求解或实质扩大范围时才询问作者。

## 8. 实际效果验收

### 比较设置

- 基线已发布 v0.11.0，候选本版；每对输入、宿主模型/设置、工具权限、工作预算一致并记录。
- 主任务包含 2–3 节相互关联的结果讨论及首尾/方法对应；另一任务检查迁移，可只做关键小节。
- 优先尚未试写的问题/保留材料；熟悉项目如实称已知项目新任务，不称陌生领域盲测。
  生成端不接收最终论文答案或评价结论。
- 保留首次输入/输出和失败；条件允许时对评阅者隐藏版本标签，不隐藏科学定义与来源。
- 在生成前固定任务必须解释的关系、不可支持的推断、数值锚点，避免看结果挑标准。

### 标准

1. **科学硬错误**：交付范围内关键数值、单位、case、统计域、图文对应无未解决错误；
   不编造方法/文献/机制，不将项目真实缺证包装成验证完成。
2. **论证效果**：逐段比较关键关系、互补/反向结果、证据范围内机制、实际文献对照，
   列出具体改善与作者仍需改的句子，不用字数、测试数或模型自评分替代。
3. **跨节一致性**：方法足够读懂结果；引言问题得到回应；摘要结论不扩大结论或堆所有数值/限制。
4. **使用负担**：记录临时脚本、编译后手改、技术重试及作者科学修正项；新长表不需专用 pivot，
   既有路径不更难用。时间仅真实测量，不倒推节省百分比。
5. **格式**：实际页无裁切、遮挡、错误对齐、损坏公式；段落属性/字号/分页可读。
   页数减少不是质量指标；正常章节或大图留下的空白不机械判错。

默认一次集中作者/外部阅读和一轮针对性修复；新增硬错误必须修复报告，
但不得更换任务、无限润色制造成功。两版同样好时只报告真实易用性/格式收益。
科学链目标未实现不能声称完整达标，须说明具体障碍并与作者决定缩小或继续；
没有可辨识产品收益，不仅为增加版本号发布。

## 9. 验证、交付和恢复

- 定向测试：混合单位/重复/缺失/原行定位/精度/源变更传播；现行温度语义；
  当前依赖稿与文献定位进入上下文；显示默认兼容/尺度不丢；长短表与图注分页。
- 上下文测试仅验证结构与版本，不证明科学推理。实际页面检查不能由结构断言替代。
- 原有 section/manuscript 路径保持可用，技能/参考随包，搬迁后数据、图件、文献定位有效。
- 发布沿原有 Windows/Linux Python 3.10–3.12 CI、Ruff、隔离安装和公开例子。
  已通过同输入检查不反复重跑；正式分发使用成功 main CI 的精确产物。

交付：通用代码/技能；可运行、可搬迁的公开数据/脚本/图表/整稿示例；
实际审阅的 DOCX/PDF（可用渲染环境）；简短效果比较与剩余证据需求。
录制草稿回放明确标注，不能冒充每次运行会自动调用模型生成新稿。

本文件末节记录完成、验证、问题、下一步；私有输入仅更新现有私有索引，总则只加恢复指针。
原始 CFD/P04 和用户精修不改；工作限定唯一仓库及必要工作树。

## 10. 保留但不并入本版的目标

原生求解器只读导出、空间/瞬态/多相拓展、Word 局部修改回收、真实期刊返修、
三类异构项目验证，继续原路线，出现对应材料/事件后实施，不由本版虚拟闭合。
v0.12 不等于通用成熟版，应证明更好的论证和更低使用负担，而非更多软件流程。
