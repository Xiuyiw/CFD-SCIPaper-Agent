# v0.14 实施计划：从普通 CFD 材料到首次完整图文候选稿

2026-10-01。作者已批准研发方向与13结果试用范围；T2/T3已实现，当前状态见第7节。
已发布基线为 v0.13.0（本地 main：b54a2d4）。方向依据见
[首次整稿研发建议](V0_14_FIRST_MANUSCRIPT_PLAN.md)。本文件是本版执行顺序入口，不替换历史路线。

## 1. 本版要交付什么

作者提供已有结果、可用方法资料和粗略研究意图，宿主主动完成材料理解、研究主线设计、
判别分析、图文组织及逐节写作；程序复用已有计算、来源、数值绑定和稿件结构。
最终得到一份科学范围明确、实际嵌有图表、可编辑且可继续修改的完整候选稿。
这里的“完整”是问题—方法—发现—讨论—结论闭合，不是达到固定页数或承诺投稿就绪。

本版三个可见改进：

1. 首次组稿不再由宿主反复抄写计算定义、result_ref 和跨节引用，也不要求作者填写 JSON。
2. 首稿通过互补的场/剖面/整体量与真实文献组织论证，不只是数字清单和反复的限制说明。
3. 在真实首次整稿中验证图、表、公式、引用及 Word 版式，并完成一次局部续改和恢复。

科学质量来自正确分析和宿主判断；程序负责可复现运算与机械连接。不得将手工修好示例
称为产品升级，也不得将技能文字变长或测试数量增加称为写作深度提升。

## 2. 已有能力与本版最小新增

| 已有能力/依据 | 本版处理 |
|---|---|
| materials、analysis_suggestions 和 analysis_section 已能生成带来源的写作输入 | 复用；仅修真实任务暴露的入口或算子缺口 |
| manuscript.py 已支持 spine、共享文献、跨节绑定、当前上下文、整稿组装和续改 | 保持兼容，不另造稿件状态机 |
| material-analysis/prepare_manuscript.py 演示了桥接，但含手写 manifest、章节映射和录制正文 | 抽取通用的机械组稿 helper；录制正文不能成为真实试用的答案 |
| 五个内置技能已有空间判读、多证据、文献角色、章节职责和格式指导 | 检查实际调用和输出；不再重复添加同义规则 |
| figure_tasks 与已有 DOCX/PDF 路径可用 | 接入真实图件并检查最终版面，不研发万能绘图/排版引擎 |

工作重心仍为 55% 科学理解、25% 绘图写作、10% 易用性、10% 必要可靠性。
该比例用于选择任务，不作为代码行数、文档量或审批文件数量指标。

## 3. 执行任务与依赖

### T1 — 选择首次整稿任务，明确材料能回答的问题

主控负责；只读现有材料索引和相关数据，不重扫整个 P04，不重跑求解器。

- 优先检查已有散热案例中尚未向执行者提供成稿的、可同时使用整体响应与空间信息的任务。
  “有多个工况”不等于证据足够，须确认方法、比较条件、实际场图/剖面及文献可访问情况。
- 优先由宿主从材料提出研究问题及可支持范围，再由作者确认；不要求作者预先完成分析。
- 壁温、压降等定义尚有冲突时，不替换数值、不扩大主张；继续不受影响的分析。
- 记录所选问题、关键比较、图件用途、文献角色及最小缺证项，放在本次试用 README，
  不创建新的审批注册表。缺证不影响问题主体时，缩小主张后继续。
- 若已有材料不足以支撑完整候选稿，直接指出缺什么、为何重要；不得把短小节包装为整稿成功。

完成条件：有明确可执行任务和材料位置；执行者不收到旧版最终正文/评价答案。
主控知道该项目，故只能称“已知资产上的隔离首次写作试用”，不能称陌生领域验证。

### T2 — 将科学指导变成实际分析与章节设计

科学支线 A 负责。读现有技能后按 T1 的真实问题查缺，不预设必须改多少条规则。

- 以已有 proposal、PaperSpine、duties、evidence_notes 表达问题与证据，不新增科学对象体系。
- 每项分析说明它能区分什么：例如几何面积作用与平均通量作用、整体均值与局部峰值、
  反应增强与位置迁移；不强制每个领域采用同一组指标或竞争假设。
- 检查定义、控制域、权重、分母及可比条件；差值和百分比不是两份独立机制证据。
- 研究结论与直接观察、物理解读、待验证解释分层；文献分别承担背景、方法、比较或验证角色。
- 阅读实际可用图像和文献，不凭图名或摘要填充机制。引言的缺口与结论由实际结果决定。
- 按需定向更新 `skills/cfd-paper-workflow/`、`skills/cfd-qoi-physics/`、
  `skills/cfd-evidence-writing/`。若现有规则足够，改进示例和任务调用，不重复堆规则。

完成条件：具体分析能服务科学问题；各节职责不重复；出现矛盾时有解释或明确缺证。
验证采用段落、图件和源数据判断，不能用关键词计数或宿主自报 PASS 替代。

### T3 — 实现分析输入到首次稿件的薄桥接

工程支线 B 负责专属模块与测试，主控负责 CLI 和公共整稿模块。
建议新建 `src/cfdpaper/publication/manuscript_seed.py`，复用已有准备/组装函数。

最小接口设计：

- 宿主给出稿件标题、现有 PaperSpine、章节职责、选中的 section-input 路径、必要的跨节
  evidence_bindings，以及可选共享文献/术语。科学选择由宿主完成，不自动取第一个指标为核心结论。
- helper 接收宿主精简的组稿说明，复制选中的写作输入及其实际依赖，生成现有格式的
  manuscript-input、drafts 映射与写作入口；不生成假正文、假引文或假批准。
- 计算、单位、result_ref、原始局部证据 ID 和 figure ID 原样复用；不同章节同名局部 ID
  可以合法共存。重复章节 ID 或跨节歧义报出具体位置，不能静默合并或猜测对象归属。
- 源路径可来自不同分析输出目录；输出内部使用可搬迁相对路径。不能仅复制 input.json
  而漏掉数据、图件或其定义文件。仅复制已有依赖，不整包复制科研项目。
- 尚需宿主写作的章节明确保持未完成；不制造空壳全文。Methods 等非分析章节沿用既有
  section-input，宿主只补充必要证据和内容，不复制 Results 的计算定义。
- 草稿已有时保留原内容，缺少时交给现有写作上下文入口生成；不冒充自动生成论文。

入口采用现有 `cfdpaper write --artifact manuscript` 下的 `--outline`，
与 `--manuscript-input` 互斥；宿主负责传入结构化说明，作者只确认科学问题和稿件。
原命令保持可用，不新增根命令或第二个调度器。

修改位置：专属模块和 `tests/publication/test_manuscript_seed.py`；主控修改
`src/cfdpaper/cli.py`、`tests/test_manuscript_cli.py` 和必要的 manuscript.py 接线。
公开示例优先扩展 `examples/material-analysis/`，不另造重复教学工程。

完成条件：至少两个分析输入及一个方法输入可机械连接，宿主不手工重建数值映射。
测试覆盖输入保真、同名局部 ID、重复章节、共享证据别名、文献/图件依赖、重定位、
原文件不变及旧入口兼容。范围由实际故障决定，不加与该功能无关的通用安全平台。

### T4 — 接通有用途的图件和实际出版格式

主控整合，A 提供图文目的，B 仅处理桥接导致的资源传递问题。

- 所选任务应实际使用互补证据；例如一幅场/剖面比较和一幅回答幅度或权衡问题的定量图。
  图数由科学需要决定，不硬凑多面板，也不拿两点稀疏散点冒充重要机制图。
- 复用 `publication/figure_tasks.py` 与 `skills/cfd-figure-production/` 的工具集成。
  保留可运行脚本、source data、编辑格式及预览；外部机制图明确是解释示意，不冒充 CFD 场。
- 核查显示量/统计量、单位、色棒范围、归一化、图中工况与正文叙述；原有用户精修脚本优先。
- 最终图宽下检查字体、marker、legend、图注、分页；原生公式和表格对齐必须在实际 DOCX/PDF
  中可读。正文默认首行缩进两字符、段前后零间距；明确期刊模板优先。

完成条件：图件不是占位图，真实嵌入整稿且可读。只有结构检查不能关闭视觉问题。
没有适用场资料时，不为达标造云图；回到 T1 调整科学范围或说明为何本轮尚不足以验收。

### T5 — 隔离宿主首次整稿试用

T1–T4准备完成后运行。使用一个上下文隔离的执行者，仅获得选定材料、粗略目标和产品技能，
不获得旧稿答案、预写论证或主控逐段提示。方法定义等必要真实资料不属于答案泄漏。

- 按“材料理解→方向确认→分析与图件→Methods/Results→Introduction/Discussion/Conclusion
  →Abstract/Keywords→整稿”连续完成，不为每节单独建立审批流程。
- 保留首次完整输出及阻断记录。只记录实际发生的协议重试、主控救场、作者必要澄清和修订，
  不设虚构零人工干预目标，不隐瞒主控补写工作。
- 当前会话过长时从现有 CONTINUE.md 和稿件上下文恢复，不重新制造全部输入。
- 生成正文、适用补充材料、图件/来源数据/脚本、DOCX 和实际 PDF 预览。

完成条件：整稿可独立阅读，科学问题有回答；源表中的关键值、单位、工况及图表引用无已知硬错。
完整度由内容和证据决定，不能凭章节数量或文件生成成功宣称通过。

### T6 — 一次集中外审、产品修正和局部续改

主控负责汇总，可将完整评审包交给外部 AI；无需组织常驻三层审查团队。

- 评阅者获得整稿、实际图件、关键原始表、方法定义和可访问文献支持；反馈保留全文，
  不仅保留压缩 JSON。看不到图像/全文等限制必须说明。
- 评价问题是否重要、分析是否有判别力、单图/单段是否解释物理、多图是否互补、
  文献是否真正支持、整篇是否重复或过度防御、格式是否可投稿阅读。
- 可复现的机械错误修产品并加相关测试；宿主错误优先修技能调用、示例或指导。
  项目缺证单列，不能当软件 bug，也不能靠润色消除。
- 集中修一轮后复查被修改处和受影响部分；科学硬错未解决不得发布主结果已达成，
  但不为审美偏好无限循环。若暴露新范围，停止扩展并交代未完成项。
- 再做一次作者指定的局部修订与一次搬迁/换会话恢复，检查非目标章节及用户改动保留。

完成条件：明确区分产品变化、宿主修订和科学缺证，留下可核查的段落与图件实例。
未做同输入、同模型和同预算配对试验时，不声称比 v0.13 更快或科学深度全面更强。

## 4. 分工、衔接与范围控制

顺序：T1 → T2/T3并行 → T4 → T5 → T6 → T7。
主控独占 CLI、manuscript 公共接线、版本及发布；A 负责技能/科学任务评价；B 负责薄桥接及专属测试。
首次试用时结束开发支线，使用独立执行上下文；总并发不超过主控加两个短支线。
共享文件修改由支线提出具体需求、主控整合，避免互相覆盖。

只在三个实质节点向作者集中汇报：任务/问题范围选定，首稿和外审结果，发布完成/真实阻碍。
执行中保持简短进展消息；普通实现和已批准范围内的修复不反复要求“继续”。
新求解、重大定义冲突、授权范围外数据使用及显著扩大研发范围才额外询问。

阶段完成写入现有项目恢复入口：做了什么、真实结果、剩余问题、下一执行点。
提交按有意义改动组织，不预设固定提交数量，不制造多套状态台账。

## 6. 验收结论应如何书写

最终汇报分别回答：

1. 产品：新增了哪些可运行能力，是否真正减少首次映射工作？
2. 科学：哪些具体段落/图件完成证据综合，哪些仍缺验证或只能定性解释？
3. 交付：实际整稿格式如何，局部修订和恢复是否保持其他内容？
4. 使用成本：作者做了哪些必要判断，主控有没有代写胶水或救场？
5. 泛化：试用是已知项目还是陌生项目，哪些物理类型仍未验证？

v0.14 不并行开发模型 API、原生 Fluent/STAR 提取、Word 任意编辑回收、投稿系统自动操作。
陌生非燃烧器、瞬态/多相的后续验证目标保留，不因当前材料完成而关闭。
不预先承诺工时或“全部成熟”；T1完成后根据材料缺口和必要代码量给出剩余工作估计。
