# v0.6.0 之后：从结果小节走向完整 CFD 论文

2026-09-13；状态：**v0.7前两批已实施：多章工作区、真实诊断材料写作与绘图Skill调用；尚未发布**。
代码基线：v0.6.0，`a8643d54a6e374b04dc825b07c61b7e99acaf253`。
本文件是后续规划入口，保留既有 V2 目标、v0.3 外部评审及 v0.4–v0.6 事实，不重写历史。

## 1. 真实判断与应纠正的路线

v0.6.0 是可用的“宿主 AI 辅助科学分析与结果小节生产工具”，不是完整论文写作 Agent。
它已能消费现成导出材料，选择有定义的分析，执行有限计算并生成可编辑小节；
缺口不是再增加几个句式，而是将各节组织成同一篇有科学主线、文献支撑和统一引用的论文。

此前的窄切片使软件逐步可用，却也造成四个偏差：

1. 以局部链路完成与 CI 通过代替整篇论文产出的进度感；版本号增长不等于写作成熟度。
2. 过度依赖已经熟悉的 P04/散热内容，容易把手工修订效果算给产品，或反复使用同一“盲测”。
3. 为控制事实错误保留过多内部词和限制，挤占流畅、深入的物理讨论。
4. 绘图只接通少量默认形式，面对真正的机制关系仍可能退化成两个点的大图；
   格式检查又曾只关注能生成/无裁切，没有检查出版尺寸下的视觉与段落排版。

新策略：**全稿论证组织为主线，外部绘图能力作为并行可替换工具，格式从第一份多章节产物开始验收。**
继续执行 55% 科学理解、25% 绘图写作、10% 易用性、10% 必要可靠性；比例用于工作优先级，
不按代码行数建立新门槛。只保留原有三个作者检查点，不复制 V1 的注册/晋升体系。

## 3. 完整写作模块的八项差距

| 能力 | v0.6.0 实际状态 | 还需完成的交付 |
|---|---|---|
| 论文科学主线 | `publication/spine.py` 有角色和依赖验证，但没有接通全稿工作流 | 选题→可检验问题→贡献→章节职责→证据图谱，真实调度多个章节 |
| Methods | 小节可携带文字与源文件，但没有方法专用生产链 | 几何/物理模型/网格/边界/数值设置/收敛与验证→可复现而易读的方法节 |
| 文献与 Introduction | 小节文献 token 与局部编号可用；没有共享书目或原文支持关系 | 给定文献的身份、原文定位、支持范围、研究缺口与全稿引用；不能只靠标题/DOI生成文献论断 |
| Results/Discussion | 已可写多证据小节；自由文案的机制正确性仍需专家判断 | 多小节递进、跨图论证、替代解释、边界与文献比较，不是每节重复同一种模板 |
| Abstract/Conclusions | 角色名称已有，尚无独立依赖链 | 从当前结果/讨论提炼贡献和关键证据，解决首尾不一致、重复和夸大 |
| 复杂科研图 | 现有单面板 renderer、真实图导入与 custom 选择 | 外部 Skill 实际出图、源数据绑定、可编辑源回收与全文尺度统一 |
| 全稿传播/排版 | 单包数值重算、DOCX表格/公式已可用 | 全局图表式与文献编号、来源更新后的受影响段落、正文/摘要/结论同步和单一全稿 DOCX |
| 整稿自审/返修 | 小节外审建议可回收；根 review/revise/export 仍是占位命令 | 一次有边界的全文自审与定向修正；真实审稿到达后的修改—回复闭环后续再接 |

代码定位：`cli.py::write_project/_write_section_action`、`publication/section.py` 的
`prepare_section/assemble_section/export_section_docx` 是已接通链；
`publication/export.py::export_manuscript` 是消费已提供正文的 Markdown/LaTeX 库，不是全稿写作器，
也不是全稿 DOCX。`review.py` 与 `revision.py` 的对象/初始化不得列成已可用完整功能。
旧 `docs/limitations.md` 仍有 v0.5 标识，文档入口漏列 v0.6，需在下一开发批次同步，
但不因此否定已交付的 v0.6 能力，也不单独为此新发版本。

### 完整写作的最低定义

作者提交成熟结果、必要方法材料和可核实文献后，Agent 能完成：科学问题确认、整稿骨架、
逐节候选稿、真实图表及引用、单一可编辑全文、一次外部/作者审查后的定向修改。
作者仍确认科学选择和最终稿；未知模型、未取证机理、无全文支持的引文不能靠流畅文字补全。
论文可写和论文可发表不同；案例证据不足时，可以完成已支持章节并给具体缺口，不包装成投稿完成。

## 4. 复用而非重造

### 本地已有能力

- 延用 CSV/材料读取、SQLite/FTS、当前比较与计算、`result_ref`、宿主任务包、小节 Word renderer。
- 接通现有 PaperSpine，不另建第二个章节系统；Section 的表格、公式、图片与样式继续复用。
- 外部评审保留原始全文意见，再去重为行动；不能只保留少量 JSON 摘要，不能自动采用所有建议。
- 作者精修源文件优先；全稿更新不靠不断拼接和全量重建用户已修改 Word。

### 外部能力

绘图采用 [独立集成研究](FIGURE_SKILL_INTEGRATION_STUDY.md) 的两个首批路径：
科研数据图 Skill + Matplotlib；原理示意图 SVG/draw.io Skill。
不自研可视化编辑器，不让 API 依赖变成普通科研数据图的启动条件。

文献样式优先复用 CSL/citeproc；[Pandoc 官方文档](https://pandoc.org/MANUAL.html#citations)
提供 BibTeX/CSL JSON 与引用格式化能力。先从作者/Zotero 已导出的书目和可读原文开始，
利用现有宿主检索能力补缺，不新建全网文献爬取平台。
Pandoc/Quarto作为已有工具的可选调用，不重写 CSL 引擎、不捆绑大套工具链；
默认仍保留现有 Word 对象能力。采用前只做一次本项目图表/公式/引用样例试验。
格式化书目不等于已经验证文献支持关系，静态引用也不冒充 Zotero 动态域。

## 5. 后续详细顺序（版本为建议目标，不代表已经批准或交付）

### 第一阶段：v0.7.0——图件集成与可持续编辑的论文工作区

主交付：一个从现成分析到多章节候选文档的入口，并完成真实的外部 Skill 图件回收。
不是又一个只有目录或提示词的版本，也暂不承诺完整引言与可投稿全稿。

| 批次 | 输入→实际工作→输出 | 最小验收 |
|---|---|---|
| 7A 全稿骨架 | 作者问题、现有证据和小节→接通 PaperSpine 与共享术语/引用身份→章节职责与可恢复宿主任务 | Methods与至少两个不同职责的结果小节能各自生成并汇入同一文档；不复制已定稿段落当生成结果 |
| 7B 图件后端（并行） | 已确认数值关系/概念关系→调用选中的外部 Skill→可编辑图及源数据/脚本/图注 | 一个数据型组合图和一个示意图实际导出；更改局部标签后其他科学内容和布局保留 |
| 7C 方法写作 | 现有模型、边界、网格、V&V材料→宿主组织方法→段落和必要方法表 | 初读者能识别模型与比较条件；所有表至少有一次有效正文引用；缺失条目不被补造 |
| 7D 多章装配 | 多章节草稿、共享图表与现有样式→统一编号/层级→DOCX/PDF预览 | 更换章节顺序后图表引用仍正确；正文两字符缩进/零段间距，图注/标题不继承；实页预览无明显问题 |

最低共享字段在7A按现有对象补齐：稳定 section/figure/table/equation/reference ID、角色、来源关系、
当前稿内容与作者编辑状态；先不设计通用工作流 DSL。
7B 不等待7C写完；7A/7C也不因某个图像 API不可用而暂停。至少一个无新付费 API 的路径可执行。

### 第二阶段：v0.8.0——文献支持的完整论文候选稿

| 批次 | 输入→实际工作→输出 | 最小验收 |
|---|---|---|
| 8A 文献证据 | BibTeX/CSL JSON、作者提供的全文或片段→身份去重、原文定位、论证角色→共享书目与引用 | 同篇文献跨章只有一个身份；撤回不支持目标句的引用；元数据未知不自动补写 |
| 8B 引言与讨论 | 研究范围、文献证据、当前结果→研究现状/缺口/问题与证据讨论→非模板章节 | 引言不是文献列表；讨论区分观察、定量、解释与文献支持，必要时提出竞争解释和最低补证 |
| 8C 摘要/结论 | 已确认的结果、讨论与范围→少量关键锚点和贡献→摘要、关键词、结论 | 不新增结果，不重复大段方法；模型敏感性不冒充验证、离散最优读数不变成连续最优范围 |
| 8D 定向传播 | 一项源值/定义/术语或引用改变→定位受影响处→更新建议和新稿 | 数字变更同时到达相关正文/表/图注/摘要/结论；涉及论断的句子交宿主重评，无关作者段落保持原样 |
| 8E 全稿交付 | 上述各节、图表和书目→统一引用/格式→含实际图表公式的整稿DOCX与PDF | 形成完整论文候选稿，不是多个section.docx合集；作者能直接进行逐节人工审查 |

首个整稿案例优先采用 P04 已有完整材料作已知回归，考察组装、文献角色和全章一致性；
不以“接近其最终成稿”直接证明泛化或原创科学水平。散热案例仅按实际成熟范围成稿，
科学缺口限制结论而不是阻断全部已支持内容。

### 第三阶段：v0.9.0——真实整稿试用与有界自审

1. 接通根 `review`：先查科学硬错误、文献支持、图文一致与章节遗漏，再查重复/语言/版式；
   每次审查产生有限具体问题，只修实际问题，不无限模拟审稿人。
2. 每节可导出自包含外审包：正文、必要原表、原图/图注、文献支持片段及问题；保留外审全文。
3. 在没有目标成稿的新任务上，用干净宿主生成首稿，再由作者/外部 AI评价；已用 P04/散热回归不再称盲测。
4. 记录科学实质修改、遗漏论点、格式修改、人工介入和实际耗时；没有计时不报告节省比例。
5. 根据真实试用失败补齐任务所需分析算子或输入适配；不能为凑版本支持度补造案例。

原生 Fluent/STAR提取、任意三维场/瞬态分析、全自动检索、LaTeX完全等价输出都不是首篇
完整 Word 候选稿的隐藏前提。需要新增空间/时间算子时，用具体任务指定控制域、权重和单位，
复用成熟工具而非把所有求解器接入一起做。

真实期刊意见出现后再接 `revise` 的意见矩阵、修订段落与回复定位。
在至少三类异构真实项目（内流、传热、瞬态/多相）通过前，不宣称广义成熟1.0；
这一长期目标保留，但不能再次阻碍可用小版本和完整写作功能交付。

## 6. 单图、单段与全稿怎样同时有科学深度

- 单图：明确一个值得读的关系；若无真实数值/场结构支撑复杂机制，则用小表/正文，不用装饰补足。
- 单段：先说明读者能观察的变化，再给最有用的定量锚点，解释其物理意义及必要的替代解释。
  不强制每段套“观察—数字—文献—限制”四句模板；段落服从章节职责。
- 单节：不同图分别提供现象、量化、诊断与解释，避免把所有数字逐一复述。
- 全稿：引言提出的问题确由方法和结果回答，摘要和结论只提炼这些答案；
  相同限制选择最合适位置解释，不在所有章节反复防御。
- 科学支持不足时：写清已经可得的现象和条件，给最低必要补证；不因需要更深机理而编造证据。

这些是宿主专用写作技能的行为与作者评价重点，不尝试用禁词正则或模型自评分证明“出版级”。

## 8. 内置技能与分工

仍以四个已有 Skill 为基础，不因角色增加而复制完整工作流：

- `cfd-evidence-intake`：材料→case/方法/比较定义，任务相关的关键缺口。
- `cfd-qoi-physics`：从物理问题选诊断；在有定义的原表/场证据上计算和解释。
- `cfd-figure-production`：按图件类型路由至外部技能，回收可编辑输出，连接正文图件职责。
- `cfd-evidence-writing`：按需加载 Introduction/Methods/Results/Discussion/Abstract-Conclusions 参考，
  不把整套大提示词复制进每项任务；文献能力形成独立薄模块后才增加专用 Skill。

下一轮推荐主控+A/B三条线，不需要更多常驻代理：

| 角色 | 独占职责 | 交接内容 |
|---|---|---|
| 主控 | 公共对象、CLI、全稿装配/传播、版本范围和整合 | 当前共同接口、真实可运行产物、剩余科学缺口 |
| A 科学写作 | 章节职责、方法/文献输入、宿主任务、P04/散热评价 | 有依据的首稿与定向测试，不改共享renderer/CLI |
| B 图件集成 | 外部Skill裁剪/署名、后端调用与回收、图件局部修改/最终尺寸 | 真实图件、脚本/编辑源与相应验证，不改科学记录 |

主控在首批确认文件边界；共享文件单一写入，不把同一个示例脚本拆给多人同时写。
需要上下文隔离时使用新执行任务，任务包只带本批输入/目标/可写文件/完成标准，不复制超长历史聊天。
恢复记录复用本计划状态区；一个有效里程碑一次汇报，不要求作者反复说“继续”。

## 9. 完成标准与停止条件

科学质量和成稿质量分开记录，但都必须通过：

- 关键数值、单位、case ID、统计域、图文与引用无硬错误。
