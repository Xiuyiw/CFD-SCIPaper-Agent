2026-09-13。目标版本 v0.6.0；状态：**实现已完成并合并主线，PR支持平台及安装检查全部通过；交付以v0.6.0标签、Release与对应主线CI为准**。

## 1. 本阶段要解决的用户问题

作者提供现成导出表、已有图件和方法说明，即使尚未整理完整科学问题、列映射或输入 JSON，
Agent 也应能先理解材料，提出少量值得研究的分析，再把作者选中的方案接入现有计算、绘图和小节写作。
不能再次要求作者先完成全部科学整理，也不能用文件清单或流畅段落冒充物理理解。

预期路径：

**结果文件夹 → 材料摘要与定义定位 → 1–3 个有依据的分析建议 → 作者选择/澄清关键歧义 →
确定性计算 → 图件职责与解释 → v0.5 小节和可审阅 DOCX。**

已有证据支持不足三个建议时不凑数；完全不足时提供明确的最低缺口，而非虚构选题。
分析建议不是整篇论文选题，不代替现有 manuscript-topic 批准。

## 3. 最小功能设计

### A. 读取现成材料

- 复用现有索引和 CSVAdapter；完整计算列摘要，向宿主仅提供有来源的适量样例与统计。
- 列出列类型、显式单位、缺失情况、候选工况/分组及可定位的定义说明。
- 文件名、列名和数据形态只能提示可能含义，不能单独确立面积平均、积分、空间域或因果机制。
- 只读原件，沿用已有项目输出目录和恢复机制，不新建登记平台。

### B. 宿主提出科学分析建议

每项建议只需说明：科学问题、比较对象、数据与定义依据、拟计算量/分组、预期图件作用、
能回答什么、不能回答什么、最低缺口。推荐一个优先方向并说明物理价值，不以可算指标数量排序。

建议要区别三种证据：已有观察、由已定义量可计算的关系、仍需额外数据支持的解释。
例如面积、平均通量和积分输运量的分解有助于解释差异，但数学恒等关系本身不是新机理证明。
没有数值读取能力的视觉观察不能替代定量计算；未能查看图像时必须说明，不能声称已读图。

仅对影响所选分析真实性的缺口提问；未知定义可暂缓相关计算，其他独立建议照常推进。
作者已有明确目标时直接围绕目标分析，不强制重新选题。

### C. 接通计算与写作

- 将作者选择和已确认语义转换为现有 table_calculations、result_ref、图件及段落职责输入。
- 复用已有比较/单位/趋势检查；已知不可比工况不得在新入口绕过检查。
- 只在真实选定分析确需且现有工具不足时补一个通用计算操作，禁止通过执行任意模型代码补算。
- 维持 v0.5 的数值从源表到正文绑定；结果改变后重新生成，受影响文字不能保留旧数。
- 给出真实图件和小节 DOCX，不以计划文件或材料包作为本阶段最终功能交付。

### D. CLI 与内置技能

不新增顶层命令。优先在 inspect 提供材料摘要，在 plan 提供与论文选题明确区分的分析建议模式；
具体选项在首批实现前按现有 CLI 确认，保持旧默认路径、输出和批准语义兼容。

宿主 AI 可以在 Codex 或其他本地 Agent 中工作，不强制新购 API 或绑定某个模型。
无模型时材料摘要和已定义计算仍可用；不能把确定性列扫描宣传成自主物理推理。

直接更新已有 cfd-evidence-intake、cfd-qoi-physics 两个 Skill 的适用入口：
允许先提议 QoI，仍不允许补造缺失定义；保留已有锁定 QoI 的执行路径。
复用 cfd-figure-production、cfd-evidence-writing；不另建重复技能集或新的作者审批层。

## 6. 怎么判断真的变好

同时记录科学质量、人工负担和成稿质量，不以测试数量或输出文件数替代效果：

1. 未预填完整 JSON 的合成陌生表可得到来源正确的字段摘要和有依据的分析建议。
2. 改变列名/材料组织仍可通过说明识别语义；缺少单位或统计域时不猜测，问题明确且局部化。
3. 对散热现成表能提出积分量与平均量可能反向变化的分析，并区分恒等分解与因果解释。
4. 从选中建议真实调用 public pipeline；数值、单位、case ID、图文引用无硬错误。
5. 改一项公开源值重新生成，绑定计算、图件和引用数值正确传播；不是仅改单份报告。
6. 不可比、重复/缺失记录、未明确的积分域等问题不会被新入口静默跳过；复用已有错误测试。
7. 记录作者实际输入了什么、补答了几个实质问题、改写哪些分析和段落；不预设虚构的效率提升百分比。
8. 解释能说明关系、支持与替代解释，少量数值有用途；不把“更大”一律写成“更好”，无审计腔和重复防御。
9. 成稿实际检查字号、单位、公式、图表引用及分页，沿用 v0.5 真实尺寸标准；测试通过不等于出版级。

公开样例使用合成数据；真实私有原表只读。自动测试覆盖实际新增行为，整合后做相关回归；
发布验证只在发布候选形成时运行，不在规划阶段重复跑已通过的全量发布检查。
