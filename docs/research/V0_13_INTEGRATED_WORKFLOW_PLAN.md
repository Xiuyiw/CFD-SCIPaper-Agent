# v0.13 研发建议：从工具集合到可用的科研写作流程

2026-09-30。状态：M5支持平台集成通过，按有界功能范围收口。独立首稿科学深度优势未证实。
基线：已发布 v0.12.0，main/tag 为 fb05303。
接续 [v0.12 计划](V0_12_DEVELOPMENT_PLAN.md)与
[成熟性路线](POST_V010_DEVELOPMENT_PLAN.md)，不重做已交付功能。

## 1. 产品目标与判断

目标不是自动拼出一篇完整文本，而是：作者交来成熟 CFD 结果和已有研究资料后，
宿主 AI 能主动识别研究问题、设计有意义的分析、组织图文、处理作者反馈，
交付科学边界清楚、格式规范、可以继续修改的论文候选稿。

成功的一体化流程应做到：

- 专业：数量、定义、比较对象和推理成立；文献确实支持对应论断。
- 好用：作者不必先写 JSON、设计全部指标或解释完机制，才能开始使用。
- 连贯：输入、分析、图件、章节和人工修改有明确的当前版本与下一步，不反复搬运。
- 可维护：问题修在共享代码/技能，而不是只手工修好示范论文。
- 可验证：新任务上能用，首次输出和失败保留，不用版本数或测试数代表成熟度。

继续采用 55% 科学分析、25% 绘图写作、10% 易用性、10% 必要可靠性的投入优先级。
这是工作重心，不是代码行数配额。stop-that-shit 贯穿实施：不增加注册表、审批链，
不为“集成”再造一套平行的数据模型或调度平台。

## 2. 当前事实与尚未成立的假设

本轮回读了当前源码、四个内置技能的入口结构、v0.12 首次稿评价、限制与历史资产映射。
未重新扫描全部 P04 原件，也未重做试写、求解或图件。

| 已有成果或问题 | 依据 | 下一步含义 |
|---|---|---|
| 长表、计算结果绑定、当前章节上下文已能运行 | v0.12 代码、公开 connected-writing 例、既有测试 | 复用，不再重复开发 |
| 首次稿的局部衔接有所改善，但科学深度优势未成立 | v0.12 已知散热任务首次稿完整评价；两稿主要权衡均合理 | 更多上下文不等于更多科学发现 |
| 两稿仍有数值/限制重复，部分机制措辞含混 | 同一评价中具体文段 | 要检查章节论证职责，而非继续堆原则性提示 |
| 试用已提供问题和预结构化材料 | v0.12 trial README | 未证明普通作者从自己的资料夹起步也容易 |
| 功能分布于多个命令、任务包和四个技能 | CLI、analysis_suggestions、publication 模块 | 需要一条可恢复的默认入口，但不删除专家接口 |
| 模型 provider 仍是配置占位 | providers.py：available=False，generate 抛出未接通异常 | 默认使用 Codex/其他工具型宿主，不宣传独立 CLI 自动写论文 |

| P04/散热已知项目不能证明通用成熟性 | 历史回放边界 | 保留跨领域真实验证目标，不重新包装旧任务 |

待检验的产品假设是：**能执行分析与修订的统一宿主流程，比单纯分发更多材料包更有用。**
不能在实施前声称该假设已成立。

## 3. 默认用户旅程

作者的起始输入：一个材料目录、已有研究意图（允许粗略）、输出语言和已知目标期刊。
不要求先给完整科学问题、所有模型说明或指标定义；先由宿主查找现有资料。

1. **理解现有研究。** 找到实际数据、案例关系、方法、图件和文献；区分已有材料与缺项。
   向作者简明说明哪些问题现在能研究、哪些需要补证，而不是先索要一张长问卷。
2. **提出研究与分析方案。** 有材料支持时给 2–3 个实质不同的方向；不足时给一个可靠方向
   或明确缺口，不凑选题数量。作者确认研究方向。
3. **分析与组织图件。** 宿主准备机器映射，调用已有计算；选择能区分解释的诊断，
   查看真实图像并选择合适编码。作者在分析/图件方案层面确认，而非逐条命令批准。
4. **形成连贯稿件。** 写 Methods、Results/Discussion，再据实际证据协调引言、摘要、结论；
   引用、图表编号和数值沿现有路径绑定。缺证说明放在合适位置，不让全文充满防御句。
5. **一次集中自审与定向修订。** 检查具体科学、图文、文献和排版问题；修实际问题，
   保留已接受内容。交付候选 DOCX、所需 PDF 预览、可编辑图件及数据/脚本。
6. **作者续改。** 用自然语言指出图、段落或数据变化；宿主只更新受影响部分并展示变化。
   作者最终确认。真实审稿意见到达后才进入期刊返修。

默认仍只有原有三个作者决策点：研究方向；证据与图件方案；最终稿。
有重大科学歧义时及时提问，独立可完成的部分继续；不能把“少提问”变成擅自猜测。

## 4. v0.13 的一个主结果、三个工作包

主结果：**从普通资料目录开始，经实际宿主执行，完成一次可恢复的整稿写作与局部修改。**
公开示例可保留录制回放；真实宿主使用结果必须与录制示例分开报告。

### A. 让科学分析真正进入写作

复用 materials.py、analysis_suggestions.py、table_evidence.py、当前章节上下文与文献记录：

- 宿主先说清要解释的现象、目前可支持的解释、何种已有观测能区分解释。
  仅在有真实竞争解释时做对比，不给每段强制套“假说—反驳”模板。
- 由问题选择算子/统计域/比较对象，再执行计算，不能先罗列全部可计算指标。
- 读取实际场图/剖面/整体量的互补关系；同一标量的差值与百分比不算两份独立机制证据。
- 当结果反向或不一致，先查统计域、归一化、权重、边界条件和物理尺度，再决定解释。
- 图像显示量、积分量、密度量不能互相替代；标量只能支持标量层面的结论。
- 文献比较必须落到具体结果、方法或适用差异；没有全文支持就不能编造机制依据或新颖性。
- 形成一个紧凑的论证工作底稿，依托现有 proposal/duties/context 保存：
  问题→判别分析→结果→支持到哪一步→尚需什么。它是宿主工作材料，不粘贴到论文正文。
- 章节写作实际消费这份分析；方法给定义、结果给发现、讨论给解释、结论给回答，
  避免各节重复整行数字和同一限制。

工程测试验证计算与材料送达；科学解释由实际文段和源证据评价。
不增加“关键词命中即机制正确”的伪语义验证。
只有选定任务确实缺少一个必要计算操作时才增加它，不预建通用表达式引擎。

### B. 将现有能力连接成一个宿主入口

建议增加一个薄的工作流入口技能，协调现有四个技能；不把其全文复制四遍。
具体文件暂定 skills/cfd-paper-workflow/SKILL.md；是否需要额外 CLI 入口由 M1 走查决定，
不预先承诺新命令语法。

- 首先用已有 inspect --materials、分析提议、manuscript context、figure tasks、
  review 等路径完成流程；机器输入由宿主生成，作者可查看但无需手写。
- 按实际材料和用户当前意图路由：开始新研究、继续写作、改一张图、更新数据或响应反馈。
  不是每次都从 init/选题重走，也不默认要求图件才能写所有小节。
- 复用现有写作状态和项目状态，只补确需的当前材料/稿件路径、任务意图和下一步。
  不再创建另一套 DB、registry、批准文件或巨型日志。
- 同一工作目录能换聊天继续；恢复时读取当前源和作者修改，不回到旧候选。
- 引文支持、解释判断和缺失信息仍由宿主/作者处理；CLI 负责可重复的计算与导出。
- 文档明确默认运行方式是“安装包 + 可调用本地工具的宿主 AI”。没有宿主时只能执行
  已提供输入的确定性步骤；独立 API 模型执行是后续可选能力，不伪装成已经支持。

薄入口必须经过真实执行，不以“新增一个 SKILL.md”宣称一体化已完成。

### C. 把绘图、格式和修订作为同一交付

- 从论点分配图/表：只有两点的简单比较可放表格或正文，不强制满幅散点图。
  场图、分布和综合图必须有各自贡献，既不装饰性堆叠，也不为省事删掉有效证据。
- 复杂科研图继续走现有外部工具任务与可编辑资产路线，不新建万能绘图引擎。
- 保留用户图件本地精修、实际显示量和共同尺度；源变更后需要重绘的图不能标成已更新。
- 默认正文两字符首行缩进、段前后 0 pt；最终图宽下检查字号、marker、legend、色棒、
  数值/单位、表头/表注、长表续页和图注所属。期刊/作者模板有明确要求时覆盖默认。
- 通过现有定向修改路径更新章节，不全稿重写。与本次问题无关的作者句子和图形选择保留。
- Word 是可审阅输出；结构化草稿是当前再生成源。发现 Word 已被用户改动时先明确
  接收其具体修改或暂缓重导出，不能静默覆盖。通用 Word 双向同步不塞入本版。
- 只有复现的共享渲染缺陷才改渲染器；不以手调示范 PDF 代替产品改进。

## 6. 顺序、分工和停止点

| 阶段 | 做什么 | 实际交付/停止条件 |
|---|---|---|
| M1 端到端走查 | 用 v0.12 从一个未经作者预填 JSON 的材料入口执行；优先在既有真实材料中选此前未完成的任务 | 保留首次尝试；列出最影响产出的至多三个障碍，确定最小改动位置 |
| M2 科学流程与薄入口 | 先修这三个障碍，接通问题、分析、技能路由、当前稿与恢复 | 换聊天继续不丢上下文；宿主确实运行判别分析并据结果写作 |
| M3 图文与局部改稿 | 接通有科学用途的图表、全文职责、版式和一条作者修改请求 | 完整稿件及实际渲染；作者改动不被无关重写覆盖 |
| M4 配对评价 | 与 v0.12 在相同材料/宿主设置/预算下比较，另做一项不同物理问题的定向迁移检查 | 一次集中阅读/外部复审；将具体问题转为产品修复，不无限改稿 |
| M5 收口 | 文档、教程、定向回归、现有支持平台 CI 和正式发布路径 | 报告哪项效果改善、哪项仍未成立；不为版本号而发布 |

批准实施后，最多主控加两个并行执行支线：

- **主控**：用户旅程、公共接口、CLI/section/manuscript 共享连接、状态语义、集成与版本；
  决定科学缺口是否能在现有材料中解决。共享文件单一写入。
- **A 科学行为与分析**：intake/QoI/writing 的相关技能、分析入口和专属测试；
  定义/计算需求以既有源证据为准，不越界改主稿渲染。
- **B 图文交付与体验**：figure 技能与任务交付、已复现的 Word 排版问题、教程/专属测试；
  不自行改变计算定义。section.py 的公共改动由主控整合。

M1 先由主控和一个新宿主完成，不同时启动三路空转。
独立写作比较用隔离上下文、不同于实现者的执行者；不增加常驻审批团队。
每个实际里程碑简报一次，普通步骤连续完成，不每完成一个文件就要求作者再次推进。

## 7. 验收：不能只验软件，也不能要求凭空证明机制

### 使用和生产链

- 首次用户只给材料和自然语言目标，不手写 JSON 或替 Agent 解释完全部物理问题。
- 统计作者必须作出的实质澄清、手填机器文件次数、临时胶水脚本、技术重试、
  人工科学修正、无关段落被改动的数量。先实测基线，不预报节省百分比。
- 在一次中断恢复和一次源值/作者意见变化后，能继续同一个稿件，不重新开始选题。
- 不以压低提问数牺牲真实性；问题应指向真正缺失且会影响结论的信息。

### 科学与写作

- 交付范围内关键数值、单位、工况、统计域、图文/引文没有未解决硬错误。
- 每个主论点回答明确问题，有必要的数值或场观察；机制只写到已有证据支持的程度。
- 缺少局部场/验证等材料时，给最小补证建议；不能只靠多段限制文字冒充深入分析。
- 引言提出的问题在结果/讨论得到回应；方法足以读懂指标；结论不是复制摘要/结果表。
- 文献的真实内容和作用匹配，未读全文不能被写成已核证的机制依据。
- 评阅者对照具体段落评价诊断选择、解释价值、冗余和修正负担；不得用模型自评分、
  字数、代码行数或测试数量证明“更聪明”。

### 试验范围与质量底线

- 首选一项证据足够、尚未提供成稿的任务进行整稿比较；已知项目如实标为已知项目新任务。
  若研究资料不足以支持机制识别，调整研究问题或登记缺证，不用标量任务测试不存在的场机制。
- 比较前固定必须解释的关系与禁止推断，保留首次输出。普通材料入口的效益和
  同映射条件下的写作效益分别评价，不把换宿主/换模型的提升算成产品提升。
- 由作者或可用的外部评阅者看匿名版本；若只有知晓版本的主控评价，要注明该限制。
  至少提供逐条修正数量与文段实例；小样本不宣称统计显著或通用优越。
- 公开稿件真实嵌入适用图表与引用，实际页检查缩进、间距、图宽、表格和分页。
  没有达到投稿证据要求就交付明确范围的候选稿，不宣称“SCI 已完成”。
- 一次集中评价、一轮针对性产品改进；硬错误必须修正，但不换试题、覆盖首次稿或无限打磨。
  若仍只有格式/易用性增益，按实际范围决定是否发布，不再次宣称科学深度目标已达成。

## 8. 后续路线：顺序保留，版本号不提前绑定

v0.13 后优先根据实际任务暴露的瓶颈决定一个下一增量，不一次铺开所有平台：

1. **陌生项目的迁移使用**：真实单相内流/压降、传热、瞬态或多相三类项目；
   现有 P04/散热不替代尚缺的第三类。材料不足时请作者提供非涉密成熟结果，
   不把新增求解当作软件开发前置，也不无限等待才能修可独立完成的软件问题。
2. **数据提取与更深诊断**：在导出负担确实妨碍使用时，接入一个最需要的只读求解器
   或通用场格式适配；配一个真实任务。时间/空间算子按研究需要扩展，不堆支持名单。
3. **日常协作**：有真实 Word 批注/修订需求后实现有限回收；先限定可安全合并的对象，
   冲突给作者查看，不宣称无损通用往返。原生 API 模型执行按离线宿主覆盖不足的需求再选。
4. **真实返修**：由真实决定信驱动意见→修改→图文/回复一致性，复用 P01–P04 成功经验。
   投稿点击和申诉保持作者主导。

成熟版的标志：作者能在新支持项目中稳定得到专业候选稿并可维护修改，科学硬错可控、
格式可直接审阅、实际人工负担下降；不是把所有 roadmap 项都标为完成。

## 9. 本轮交付与恢复
