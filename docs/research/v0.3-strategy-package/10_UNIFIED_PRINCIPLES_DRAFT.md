# CFD-Paper-Agent 统一总则草案

日期：2026-09-01
适用目标：V0.3 及后续公开产品
状态：外部评审候选；不替代当前 v0.2.0 公开能力声明

## 1. 产品定位

1. CFD-Paper-Agent 面向已有成熟 CFD 结果，帮助作者把结果转化为可复核的分析、图件和学术文本。
2. 它是作者在环的半自动系统，不是 CFD 求解器、无人科研系统、论文投稿机器人或专家判断替代品。
3. 核心保持广义 CFD：不将燃烧器、锅炉、Fluent、STAR-CCM+ 或任一特定物理问题写入通用科学核心。
4. 领域差异通过只读适配器、可测 Skill 和项目上下文进入，不通过放松证据边界进入。

## 2. 优先级与范围控制

1. 产品设计与验证使用 **55/25/10/10** 组合预算：55% 科学理解与分析，25% 科研绘图与写作，10% 适配与易用性，10% 必要可靠性、溯源与作者权限。
2. 该比例约束能力投入和验收，不按文件数、对象数或代码行数机械核算。
3. 必须严格执行 **STOP THAT SHIT**：只完成作者要求、当前规格包含或不做就会使交付失败的工作；证据充分后停止。
4. 不因“以后可能有用”增加框架、registry、审批层、评分平台、哈希流程、兼容层、依赖或安全声明。
5. 内部流程不进入用户或论文产物；对外只呈现科学问题、证据、判断、限制和可执行的下一步。

## 3. 科学证据原则

1. 文件存在、adapter 成功、图件导出、引用存在、文档编译或阶段完成都不是科学证据通过。
2. 工况比较必须先检查几何、材料、边界、模型、网格/时间步、采样、统计窗口和参考态；同名变量或可转换单位不足以证明可比。
3. comparison contract 中的差异必须说明是研究因素、已证明等价/无实质影响、未解决干扰还是阻断项；作者批准不能把未解决干扰变成受控变量。收敛和守恒阈值必须有项目依据和 locator，不使用隐藏默认值。
4. 每个 QoI 必须明确公式、输入、单位、scope、窗口、权重、归一化、missing policy、版本、数据来源和输入值角色；V0.3 不从离散点列猜测场积分或由模型发明公式。
5. 趋势措辞必须比较锁定的 expected 与 observed 完整序列，并使用合同声明的容差和最小样本数。端点差异、图形印象或平滑曲线不能单独支持单调、平台、峰值、连续最优或稳定边界。
6. numerical verification 与 validation 按 [NASA/AIAA CFD V&V 语义](https://www.grc.nasa.gov/www/wind/valid/tutorial/tutorial.html)独立记录：前者关注模型实现和计算解，后者关注 intended use 下对现实的代表程度。缺失网格/时间步或外部对照时，产物应降级主张；`not-applicable`必须有逻辑依据，不能代替缺证据。
7. 显示量、局部样本、派生指标和严格物理量必须分层；局部诊断不自动承担整体性能或工程边界主张。
8. 缺失数据保持缺失。系统交付最小可执行缺口，不填点、平滑、伪造引用或用流程文件补足证据。

## 4. Claim 与产物传播

1. claim ceiling 只由当前合格 evidence 和真实作者决定限制；Skill、外部 AI、QA、文件或状态不得提高它。
   ceiling 只使用`no-numerical-claim`、`directional-comparison`、
   `qualified-numerical-observation`和`supported-physical-interpretation`四档封闭映射；资格、V&V 和
   intended use 决定最高档位，写作层不能另造等级。
2. 分析、图件和写作对锁定证据是单向消费；表达层不得回写数值、单位、case、趋势或文献角色。
3. 主要数字、单位、case ID、图号和文献角色必须能回到来源、QoI 算子或已验证文献 locator。
4. FigureContract 先于绘图；每个 panel 只承担它实际显示的证据职责。图件必须交付 source data、可运行脚本、可编辑输出和预览。
5. 图件 QA 同时检查数据、叙事与视觉；渲染成功、美观或套用期刊样式不代表图件可发表。
6. 写作以已批准章节职责和证据为起点，优先交付短而完整的可辩护文本；不为显示工作量堆叠数字、引用、局限声明或内部过程。

## 5. Skill 与适配原则

1. Skill 只封装真实、重复、基础模型不能稳定完成且可验收的科研能力；能用一个参考、模板或确定性脚本解决时，不新建 Skill。
2. Skill 采用三级渐进披露：短元数据 → 工作流 → 按需 scripts/references/templates/assets；不无目的加载全部资源。
3. 每个 Skill 必须有明确触发/禁止触发、输入输出、前置证据、停止条件、工具缺失回退和正/负/对抗回放。
4. Skill 安装、加载或脚本成功不是科学验收。没有真实 CFD fixture 收益的 Skill 不进入公开内置集。
5. Skill 必须可合并、可精简、可淘汰。基础模型已能稳定完成时，只保留仍有价值的确定性脚本或方法参考。
6. 适配器使用`probe / inventory / extract(request)`边界，原始结果只读，缺字段保持缺失，并返回最小人工导出建议。
7. 适配器只解决数据进入问题，不判定工况可比、收敛、验证、QoI 或 claim。
8. V0.3 的权威执行路径是本地 Python CLI 与确定性脚本；Skill 是薄包装。跨宿主 adapter、provider transport 和额外图件格式只有在真实需求出现后进入后续版本，不得成为隐藏验收。

## 6. 作者在环与真实事件

1. 全流程只有三个作者检查点：①选题、科学问题及当前分析所需科学合同，V0.3 在此确认并锁定 candidate QoI contract；②分析后一次性确认 evidence、claims、ceiling、candidate FigureContract 和 paper spine/章节职责；通过后才锁定合同、绘图和写作；③最终论文与交付文件。
2. 执行器、Skill、checkpoint、worker handoff、外部 AI 或状态字段都不能创建作者批准。
3. 返修只由真实决定信或审稿意见触发。提交前自审与期刊返修是两个不同任务，不开启无限模拟审稿。
4. 作者可以接受、拒绝或要求重开实质问题；系统只能将“产物已生成”与“作者已批准”分开记录。
5. 作者决定必须绑定对象和版本，但这是后台可靠性，不向用户暴露额外治理流程。
6. 面向普通研究者的入口使用 case、边界、模型、收敛、守恒和来源等科学语言，通过 guided intake
   写入现有 records；系统不能判断时返回最小缺口，不要求用户学习内部 registry/schema，也不替其填入
   科学阈值。

## 7. 可靠性、溯源与交付

1. 原始求解结果和作者输入默认只读；新产物写入独立项目输出区，覆盖源文件需真实作者授权。
2. 来源、case、单位、QoI 定义、输入版本和产物依赖必须可恢复；embedding 只能帮助定位材料，不能证明数值或 claim。
3. 输入改变后，依赖的分析、图件和文字必须显式过期，不静默混用新旧版本。
   该规则必须有端到端回归：CSV、expected case set、QoI/comparison contract 或单位定义变化时，旧图文不可继续消费；输入未变时才允许恢复。
4. 一轮与当前风险相称的验证已足够时停止。不为显示谨慎而重复搜索、复审、哈希、报告或状态文件。
5. 真实 DOCX/LaTeX/PDF 导出必须在科学内容冻结后进行，并区分源文件、预览与投稿包。编译或文件可打开不提高 claim ceiling。

## 8. 公开验证与能力声明

1. 公开 fixture 必须使用非敏感数据，并覆盖正向、负向和对抗场景。私有资产只用于授权内部回放，不进入公开仓库或外部评审包。
2. 目前可用的 authorized internal positive/negative regression assets 只支持证据-图文-写作的正向回放，以及不可比工况、错趋势、弱收敛、错聚合、缺失数据与虚假批准的负向回放。
3. 尚缺稳态单相内流、换热、瞬态/多相三类可公开回放。在这些验证完成前，不宣称对广义 CFD 的全面普适性。
4. 发布说明、README、Quickstart 与 CLI 必须一致。路线图项、实验接口或内部模块不写成已发布能力。

## 9. 当前生效边界

本总则是待外部评审与作者批准的草案。它在获得最终批准前不替换当前公开说明，不授权 V0.3 实现，也不将路线图能力视为已交付。
