# Deep-dive report contract

本目录在Task 3只固定后续报告结构和路径规则，不在尚未深读时创建空项目报告。候选目录中的
`report_path`是后续Task的确定性目标路径，不表示报告或深读已经完成。

开源/学术代码报告放入`open-source/`，商业公开工作流报告放入
`commercial-public-workflows/`。文件名由候选ID生成：把非字母、数字、点、下划线或连字符
替换为双下划线，再添加`.md`。

## 每份报告的固定结构

### 1. 来源

列出候选ID、官方仓库/文档、原始论文（如适用）、访问日期、固定commit或页面定位。事实与
研究者推断分开标记。

### 2. 轨道与真实任务

说明候选覆盖的轨道、实际用户入口、输入、输出和不处理的任务。不得把README愿景或商业宣传
写成implemented。

### 3. 实际代码或文档定位

开源对象定位到入口、核心对象、一个代表性实现、测试/示例和发布边界；商业对象只定位官方
帮助中心、公开页面和可观察步骤，不推测内部代码、模型或数据库。

### 4. 架构

记录完成当前迁移判断所需的组件关系、依赖与边界。只描述公开证据支持的结构。

### 5. 输入与输出

记录接受的数据/文档、产生的状态/文件、可编辑性、来源绑定和缺失数据行为。

### 6. 科学边界

检查单位、可比性、收敛、守恒、QoI、趋势、不确定度、引用和claim ceiling中实际相关的部分；
不要求无关项目回答全部科学问题。

### 7. 状态与恢复

记录持久化、重入、陈旧输入、失败恢复和人工检查点；不适用时明确说明。

### 8. Skill、插件或适配器

记录发现、加载、参数/资源、脚本、隔离、版本和回退机制；不适用时明确说明。

### 9. 测试、示例与发布边界

定位测试/示例、当前release和README与发布实现的一致性。测试存在不等于科学正确性已证明。

### 10. 许可证与条款

记录许可证/公开条款、直接复用限制、商业或供应商锁定。商业产品只分析UX。

### 11. 优点

只列公开代码/文档可以复核且与本项目问题直接相关的优点。

### 12. 缺点与风险

列出依赖、科学边界、缺失数据、维护、许可证、可用性或过度自动化风险。

### 13. 迁移判定

只使用`direct reuse`、`reimplement`、`idea-only`或`reject`之一，并写明目标问题、
适配条件、预期收益、成本、风险和验证方法。

### 14. P04 / Gate 5 对应关系

只使用公开基线中已经抽象的正向写作/返修模式和负面科学阻断模式，说明该机制能验证或防止
什么；不得包含私有路径、案例数值、论文原文或归档内容。

### 15. 未验证项

列出因登录、付费、运行环境、许可证、数据或当前Task停止条件而未独立验证的事项。未验证项
不补写为事实。

## 停止条件

每个项目读取入口、核心对象、一个代表性实现、测试/示例和许可证后，只要足以形成迁移判定就
停止。若没有独立机制、没有真实实现或不适合当前轨道，立即降为`discovery-only`，不写平行
审计文件、不建立评分平台，也不继续全仓扫描。
