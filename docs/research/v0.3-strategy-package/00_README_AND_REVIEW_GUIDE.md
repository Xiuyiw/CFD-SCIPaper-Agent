# CFD-Paper-Agent V0.3 Strategy Review Package

日期：2026-09-01
评审对象：CFD-Paper-Agent v0.3 及后续版本的产品设计候选
当前公开基线：v0.2.0

将 ZIP 上传给外部评审模型后，请先阅读本文件，再按照
`11_EXTERNAL_AI_REVIEW_PROMPT.md` 执行统一评审；不要跳过导览直接重做产品设计。

## 1. 为什么需要这次评审

CFD-Paper-Agent 面向**已有成熟 CFD 结果**，帮助作者把可复核的数值证据转化为科学分析、论文图件和学术文本。它不是 CFD 求解器，也不是无人监督的“自动发论文”系统。

v0.2.0 已公开交付项目初始化、资料新鲜度检查、证据有界的 2–4 个研究方向候选生成、排序和作者审批。它尚未交付通用 CFD 结果解析、QoI 分析、论文级绘图、正文写作、文档导出或返修链路。本包不是在声称这些功能已经完成，而是在公开对标研究基础上提出下一阶段的可审查设计。

本次外部评审的目的不是从零重做产品，也不是比较哪个通用 Agent 功能最多。请判断：现有研究事实是否可靠，科学边界是否足以阻止错误 CFD 结论，内置 Skill 与产品架构是否能形成普通研究者可用的纵向工作流，以及 v0.3 是否被切成了真正可实施、可验收的最小版本。

## 2. 已冻结的产品约束

评审建议必须在以下约束内判断，而不是默认推翻它们：

1. 输入是已有成熟 CFD 结果；默认不重新求解，不凭空发明研究项目。
2. 产品是作者在环的半自动 SCI 论文生产系统。
3. 资源投入目标为：55% 科学理解与分析，25% 科研绘图与写作，10% 适配与易用性，10% 必要可靠性、溯源和作者权限。
4. 可比性、单位、收敛、守恒、QoI 定义、趋势和 claim ceiling 必须先于绘图与写作。
5. 原始结果只读；缺失数据保持缺失；表达层不能改写锁定数值或提高主张上限。
6. 全流程只有三个作者检查点：科学问题与分析合同；证据/claims/图件与章节职责；最终论文与交付文件。
7. 通用核心保持求解器无关、研究对象无关；领域能力通过适配器、Skill 和项目上下文进入。
8. 只完成当前交付的必要工作。不能改善真实科研任务的框架、审批层、报告和安全流程不进入前台产品。

如认为某项约束本身存在严重问题，请给出直接证据、受影响的用户任务和可执行替代方案；不要仅以“更自动化”“更完整”作为理由。

## 3. 本包如何形成

研究采用模块优先的双层漏斗：

- 宽口径发现覆盖 CFD 适配、科学分析、科研绘图、文献与写作、Agent/RAG、Skill、质量与导出七条轨道；候选达到 33 个且机制饱和后停止扩展。
- 对 16 个开源或学术代码项目进行代码级深读，定位固定提交、入口、核心对象、代表性实现、测试、许可证和实际边界。
- 对 7 个商业产品只分析官方公开工作流和用户体验，不推测内部模型、RAG、数据库或 Agent 架构。
- 共记录 63 条一手或官方来源。公开事实、研究者推断、迁移建议和未验证项分开表述。
- 迁移结论只允许 `direct reuse`、`reimplement`、`idea-only` 或 `reject`。

历史私有项目只贡献经过概括的正向/负向模式，例如数值反链、图文传播、错误趋势、不可比工况、弱收敛和虚假批准。本包不包含私有 CFD 数据、公司算例、未发表论文、原生求解文件或私人绝对路径。

## 4. 推荐阅读顺序

为减少上下文负担，建议按以下顺序阅读：

1. `00_README_AND_REVIEW_GUIDE.md`：确认评审背景、边界、方法和证据层级。
2. `11_EXTERNAL_AI_REVIEW_PROMPT.md`：锁定九个评审维度、严重度和统一返回格式。
3. `08_V03_PLUS_PRODUCT_DESIGN.md`、`09_V03_PLUS_DEVELOPMENT_ROADMAP.md`、
   `10_UNIFIED_PRINCIPLES_DRAFT.md`：评审目标架构、版本切片和统一规则。
4. `05_CROSS_PROJECT_COMPARISON.md`、`06_REUSABLE_PATTERNS_AND_ANTI_PATTERNS.md`：
   核查跨项目结论、复用机制、反模式和精确来源定位。
5. `07_BUILT_IN_SKILL_SYSTEM_DESIGN.md`：评审 Skill 是否是可发现、渐进加载、可测试的能力单元，而非长提示词集合。
6. 按需回读 `01_CURRENT_PRODUCT_BASELINE.md`、`02_BENCHMARK_METHOD.md`、
   `03_PROJECT_LANDSCAPE.md`、`04_DEEP_DIVE_REPORTS/` 和 `sources_manifest.json`；
   仅在核实基线、方法、候选覆盖、具体机制或来源时深读，不必机械重读全部报告。

## 5. 评审时应区分的证据层

- **当前产品事实**：只由 v0.2.0 公开文件支持。
- **外部项目事实**：由固定提交的源码、测试、官方规范或商业官方页面支持。
- **研究者推断**：从公开机制推导的本产品适配判断，不等于外部项目作者主张。
- **未来建议**：尚未实现，必须通过后续规格、代码和真实项目回归才能成为产品能力。
- **未验证项**：不得因为表述完整而补写成事实。

商业报告中的 `official claim`、`observable workflow` 和 `controller inference` 必须保持分离。开源项目的 API、测试或许可证存在也不能自动证明其科学适用于 CFD-Paper-Agent。

## 6. 期望的评审重点

请重点检查九个方面：事实准确性、科学边界、对标充分性、Skill 设计、产品架构、实现可行性、普通用户体验、版本切片和规则治理。优先报告会导致科学错误、产品方向错误、无法实现或普通用户无法完成真实任务的问题。不要用新增大量治理对象替代科学修复，也不要要求从零复做已经有一手来源支撑的研究。

## 7. 返回方式

请使用 `11_EXTERNAL_AI_REVIEW_PROMPT.md` 中的统一格式。每个 finding 必须包含：

- Finding ID；
- severity；
- exact location；
- evidence and rationale；
- recommended revision；
- whether new evidence is required；
- conflict with current constraints；
- adoption level。

采纳级别只使用：`must adopt`、`recommended`、`optional`、`reject`。如果没有实质缺陷，请明确写明所检查的范围和“no material finding”，不要为了显得全面制造偏好性修改。

外部评审完成后，项目主控只进行一轮跨模型去重归并和一次定向修订；任何外部模型的知名度或意见数量都不构成自动采纳理由。最终设计仍需作者书面批准，才允许启动 v0.3 实现。
