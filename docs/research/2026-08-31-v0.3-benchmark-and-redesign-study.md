# V0.3前置对标研究与产品重设计规格

状态：作者已批准研究方法，等待书面规格复核

日期：2026-08-31
适用基线：CFD-Paper-Agent v0.2.0

## 1. 目的

本研究不是立即开发V0.3，也不是罗列热门AI项目。目标是在保留CFD-Paper-Agent现有科学
证据边界、P04成功资产和Gate 5失败教训的基础上，对公开可验证的同类项目和相邻模块进行
系统比较，提炼可迁移的产品机制、技能设计、规则、接口、测试方法和用户体验，形成经外部
高能力模型评审的后续产品蓝图。

最终结果必须回答：

1. 市场和开源生态已经解决了哪些问题，采用了什么实际机制？
2. 哪些机制能改善“成熟CFD结果 → 可辩护选题 → 分析 → 图件 → 论文 → 自审/返修”？
3. 哪些做法只适用于机器学习、通用办公或从零自动研究，不适合真实CFD项目？
4. V0.3及后续版本应内置哪些专用技能、公共接口和作者检查点？
5. 如何在不恢复V1过度治理的情况下提高科学正确性、智能程度和普通用户可用性？

本阶段只产生研究、设计和外部评审材料，不修改V0.2.0生产代码，不启动V0.3实现。

## 2. 已冻结的产品前提

- 产品面向已有成熟CFD结果，默认不重新求解，不凭空发明研究项目。
- 产品是作者在环的半自动SCI论文生产系统，不是无人监督的“自动发论文”系统。
- 能力资源按55/25/10/10分配：55%科学理解与分析，25%科研绘图与写作，10%适配和易用
  性，10%必要可靠性、溯源与作者权限。
- 科学证据、单位、可比性、收敛、守恒、QoI定义和claim ceiling优先于语言完整度和流程状态。
- P04、P01–P03和Gate 5/SG_Baffle分别作为正向写作/返修经验、作者语气和负面科学阻断资产。
- 核心必须求解器无关、研究对象无关；领域能力通过适配器、技能和项目上下文进入。
- 安全和溯源是后台默认行为，不得重新成为用户面对的主流程。
- V0.3开发继续暂停，直到本研究包完成、外部评审返回且作者批准最终方案。

## 3. 研究范围

### 3.1 七条能力轨道

1. **CFD资产识别与适配**：原生求解器、CSV/VTK/CGNS、对象清单、只读提取、单位和来源。
2. **科学分析与物理解释**：QoI、可比性、收敛、守恒、趋势、敏感性、不确定度和claim ceiling。
3. **科研绘图**：figure contract、source data、出版格式、可编辑输出、图文一致性和视觉QA。
4. **文献与论文写作**：证据检索、文献角色、paper spine、逐节写作、引用和跨章节传播。
5. **Agent编排与RAG**：状态恢复、任务上下文、结构化检索、FTS、可选语义检索和供应商抽象。
6. **专用Skill系统**：发现、渐进式加载、参数/资源、脚本执行、适用条件、测试和版本管理。
7. **质量与交付**：提交前自审、真实返修、DOCX/LaTeX、图表/引用嵌入和可复现导出。

### 3.2 项目来源

- 开源项目：代码级深读，检查真实实现、测试、依赖、许可证、维护状态和接口边界。
- 闭源或商业产品：只依据官方公开文档、演示和帮助中心分析工作流与用户体验；不反推内部
  技术，不把营销主张当作事实。
- 标准与规范：优先使用官方规范、项目文档和原始仓库，包括Agent Skills、MCP、FAIR和科学
  软件相关规范。
- 学术项目：必要时用原始论文与其官方代码仓库核对方法和实现关系。

### 3.3 明确排除

- 只做摘要、聊天或格式润色且没有可迁移机制的普通AI工具。
- 无许可证、长期失效、仅有宣传README而无可执行实现的项目，不进入深读层。
- 以自动生成虚假实验、虚假引用或无限自我审稿为卖点的流程，不作为正向方案。
- 单纯按star数量、商业知名度或功能数量排名。

## 4. 研究方法：模块优先的双层漏斗

### 4.1 第一层：宽口径发现

- 按七条轨道设计独立检索式，形成约30–50个去重候选项目。
- 每个候选记录：项目/产品、URL、许可证、维护状态、主要能力、适用轨道、证据来源和初步风险。
- 闭源产品与开源项目分别记录，不使用同一“代码质量”分数比较。

### 4.2 第二层：深度分析

- 从候选池选择约12–18个开源项目做代码级深读；每条能力轨道至少有一个高相关项目。
- 另选择约5–8个闭源产品做公开工作流和UX比较。
- 深读必须覆盖入口、核心对象、状态/存储、插件或技能系统、测试、示例和发布边界；不得只复述
  README。
- 对可复用组件定位到仓库文件、类、函数或规范章节，并记录许可证兼容性。

### 4.3 评价维度

每个项目采用同一组问题，而不是统一总分掩盖差异：

- 科学正确性与缺失数据行为；
- 证据、claim和来源的绑定方式；
- 对真实已有结果的支持程度；
- 人机分工与检查点；
- 状态恢复和上下文效率；
- 技能/工具发现与渐进式加载；
- 图件、论文和可编辑产物质量；
- 可扩展性、适配成本和普通用户门槛；
- 测试、回归、许可证和维护风险；
- 是否会诱发过度自动化、虚假完成或内部治理膨胀。

## 5. 迁移判定

任何外部做法只能进入以下四类之一：

1. **直接复用**：许可证兼容、接口独立、测试充分且无需引入过重依赖。
2. **重新实现**：机制有价值，但代码、依赖、许可证或科学边界不适合直接复用。
3. **只借鉴思想**：主要价值在工作流、交互或规则，不复制代码。
4. **明确拒绝**：与真实CFD证据、作者在环或55/25/10/10优先级冲突。

每项建议必须给出来源、目标问题、迁移类别、适配条件、预期收益、实现成本、风险、验证方法，
以及与P04或Gate 5经验的对应关系。没有精确来源或可验证机制的建议不得进入V0.3设计。

## 6. 内置专用技能系统的研究目标

后续产品必须具备可发现、可组合、可测试的专业技能，而不是把全部说明塞入一个系统提示词。
本研究重点确定：

- 三级渐进式披露：简短元数据 → `SKILL.md`工作流 → 按需脚本/参考/模板；
- 技能触发条件、输入/输出契约、前置证据、停止条件和失败回退；
- 科学技能与表达技能分离，锁定证据不得被写作技能更改；
- 技能包使用相对路径并兼容不同Agent宿主；
- 每个技能具有最小正向例、负向例和回归测试；
- 技能只保留模型不能稳定完成的领域方法和工作流，随基础模型能力提高可精简或淘汰；
- 首批候选技能覆盖案例盘点、可比性、单位/守恒/收敛、QoI设计、趋势分析、figure contract、
  论文绘图、paper spine、逐节写作、文献证据、图文一致性、自审和真实返修。

技能数量、分组和公共接口只有在外部研究结束后才能冻结，本规格不预先指定数量。

可使用经过概括的成功/失败模式。

## 8. 外部AI评审设计

外部评审提示词必须要求模型：

- 区分事实核查、产品方向、科学边界、技能架构、工程可执行性和发布策略；
- 对每项发现给出严重度、位置、依据、建议、是否需要新证据及与当前产品的冲突风险；
- 不因追求自动化而削弱作者检查点和科学证据；
- 不要求从零推翻已有V0.2.0，不把特定燃烧器方法固化进通用核心；
- 标明其无法验证的外部项目主张；
- 给出“必须采纳、建议采纳、可选、拒绝”的意见分级。

多个模型的意见先建立交叉矩阵，再由主控按项目证据、产品定位和实现成本吸收；意见数量或模型
知名度不构成采纳理由。最终方案必须回到作者批准。

## 9. 质量与停止条件

研究阶段必须满足：

- 每个深读项目具有实际代码或官方文档定位；
- 公开事实和主控推断分开标记；
- 许可证和维护状态得到核对；
- 七条轨道均有对标结论，也允许结论为“没有成熟项目”；
- 每项V0.3建议能追溯到外部经验和/或P04、Gate 5证据；
- 方案不恢复L0–L4、promotion registry、synthetic master acceptance等前台治理；
- 不在外部评审返回前创建V0.3实现分支或生产代码。

当候选覆盖已足以回答七条轨道、深读达到约12–18个高相关开源项目且新增项目不再产生重要
新机制时停止扩展搜索。不得为了显示工作量无限增加仓库数量。

## 10. 验收标准

本阶段完成的判据是：

1. 对标清单可复核，深读不是README摘要；
2. 形成清楚的“借鉴、重写、拒绝”决策；
3. 内置技能体系有可执行设计而非技能名称列表；
4. V0.3+路线图明确最小切片、依赖、验收和后续版本边界；
5. 新总则保持科学与产出优先，没有治理回潮；
6. 外部AI可在不访问私有资产的情况下独立审查整个方案；
7. 作者完成外部评审回收和最终方案批准后，V0.3开发才可恢复。
