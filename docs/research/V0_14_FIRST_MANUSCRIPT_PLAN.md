# v0.14 研发建议：科学主线驱动的首次整稿

2026-10-01。状态：作者已确认研发方向；详细实施计划已形成，代码和发布尚未开始。
执行入口见 [v0.14实施计划](V0_14_IMPLEMENTATION_PLAN.md)。
基线：本地main与v0.13.0为b54a2d4，工作区在本次规划前干净。
本轮复核源码、v0.13集中评价与续稿记录，不重跑已有试验。

## 1. 判断与主结果

目前产品是可用的作者在环证据—稿件工作台，而不是已验证成熟的整篇论文研究助手。
计算绑定、原生Word、整稿组织和续改已有实现；薄入口改善了材料与技能携带。
但从普通资料首次建立完整研究主线、正确选择互补诊断并写出有深度整稿，尚未充分证明。
已有续改收益不能当作首次成稿或普适推理优势。发布成功不关闭这些目标。

v0.14只设一个主结果：作者给出现有材料和粗略研究意图，宿主主动理解材料，
经研究方向确认后，利用可复现分析和适用图件形成有文献支撑、可审阅及可续改的
完整候选稿。作者不负责填写JSON；宿主也不应反复手工复制已有计算定义和绑定。
完整指研究问题、方法、结果、讨论和结论相互对应，不是凑齐章节标题或保证可发表。

沿用55%科学理解、25%绘图写作、10%易用性、10%必要可靠性；比例是工作重心，
不是代码行数配额。执行stop-that-shit，不增加审批层、注册表或自评分认证体系。

## 2. 当前缺口及优先级

| 缺口 | 当前依据 | 处理 |
|---|---|---|
| 首次整稿主线依赖大量宿主人工组织 | v0.13集中评价：首次构造计算、绑定、章节、manifest；随后续改容易不代表首次准备成本已消除 | 本版主任务 |
| 科学讨论常停在标量复述与边界声明 | 首稿与修订对照：核心物理解释原已存在，数字和限制重复仍在 | 本版以真实段落和互补图文验收 |
| 多图、多证据与完整稿联动缺少充分试用 | 最近两节/整稿续改主要验证表格、公式、文字，并非完整图文能力测试 | 本版纳入适用的真实图件，不新造万能渲染器 |
| 文献语义支持仍由宿主查证 | literature可保存元数据、片段、定位及支持决策，不能从片段匹配自动证明论断 | 本版把现有全文/文献职责接入实际写作；不新建文献平台 |
| 结构化源与Word人工编辑不能自动合并 | 当前稿可搬迁重组装，Word改动需人工协调 | 保留限制，后续按真实批注需求做有限回收 |
| 原生求解器、一般时空/多相诊断仍不完整 | 当前以CSV/映射NPZ及声明算子为主 | 不同时扩展；真实任务证明需要后再选一个适配器/算子 |
| 无独立模型API执行 | providers.py available=False，generate仍为占位 | 本版继续宿主执行，不以接通API替代科学质量 |
| 泛化和作者劳动降低未量化 | P04、散热是已知资产；修订前后不是等预算首稿A/B | 留真实首次输出与干预记录，不宣称通用优越 |

现状核对发现的两处公开文档漂移（ROADMAP旧“v0.13未发布”、limitations旧版本开头）
已在规划阶段修正；不重复列为研发任务，不改变旧发布标签，不重跑科学试验。

## 3. 三个必要工作包

### A 科学主线和判别分析

宿主从材料归纳：研究现象、可比工况、已有解释、支持该解释的独立观测、需要的分析。
复用paper spine、proposal、duties及evidence_notes表达，不引入第二套知识或claim系统。

- 将整体量、空间场/剖面、边界条件和文献结果联合读取，不将同一数据的差值与百分比
  当作两项独立证据。
- 明确选用诊断为什么能回答研究问题；结果相反时先查统计域、权重、分母和比较条件。
- 观察、关联、物理解读和已验证因果保持区别；有真实竞争解释时才设计判别比较，
  不强迫每篇论文套同一假设模板。
- 缺证转为具体最小行动：缺哪个量、哪项比较、影响什么论断；可完成部分继续。
  不靠重复限制段落制造科学深度，也不靠语言补出没有的数据。
- 文献支持分清背景、方法依据、定性比较和直接验证；宿主阅读实际可访问原文，
  将出处放入现有literature结构。缺全文不得自称完成核证。

主要落点：五个既有skills及其references、分析任务指导、已有上下文入口。
只有真实选定分析被现有算子阻断时才增加必要运算。

### B 从已有分析建立首次稿件

复用analysis_suggestions、analysis_section和publication/manuscript的现有对象。
宿主负责研究问题、章节职责、证据选择及正文；程序承担机械映射与复用。

- 从一个或多个已选择分析的section-input复用定义、source、result_ref和图表；
  由宿主提供精简章节意图，生成现有manifest/draft入口，不让作者重建全部JSON。
- 明确同名局部ID、共享证据所有者、跨节别名及相对路径，不能静默把不同量合并。
- 方法先解释定义，结果报道发现，讨论综合证据和文献，结论回答研究问题；
  摘要与关键词最后从实际稿件更新。
- 现有上下文和续改保持兼容；资料改变后刷新数值并提示宿主重读受影响解释，
  不把数值更新等同于自由文本已正确改写。

是否新增一个CLI选项或仅新增现有API helper，由短实现规格决定；不预建新的调度器。

### C 图文、格式与交付

- 使用有科学用途的现有场图/剖面和定量图表；本题需要图就不能只用小表代替，
  不需要图也不为展示功能塞装饰图。优先使用实际图件，不只检查图像占位符。
- 复用既有绘图任务与可编辑返回机制；图中显示量、尺度、单位与正文量一致。
  不对缺失场造云图，不把机制草图当数值结果。
- DOCX逐页检查正文首行缩进、段前后间距、公式、表格、图宽下字体和图注分页；
  作者/期刊明确模板优先。JSON/XML结构通过不代替目检。
- 交付候选正文、适用补充内容、来源数据/脚本、可编辑图件、DOCX/PDF预览，
  再完成一次真实局部修订和一次跨会话恢复；不覆盖作者人工精修。

## 4. 顺序与分工

| 阶段 | 工作及产物 | 完成条件 |
|---|---|---|
| 1 确定真实任务与短规格 | 从既有成熟资产选择一个未提供成稿的新研究任务；列明输入、问题和缺证 | 输入能支撑拟定研究范围；首次稿不预喂旧论文答案 |
| 2 必要产品改进 | A科学指导和B初稿桥接并行；主控整合公共接口；C复用图文链 | 有真实输入贯通，机械映射无需作者手填，针对性测试通过 |
| 3 首次整稿试用 | 隔离宿主一次执行材料→分析→图文→整稿；保存首稿与实际阻断 | 不是七个空壳章节；数值/引用/图文可以核查，实际渲染可读 |
| 4 集中评阅与一轮修正 | 外部AI/独立评阅者看完整稿和关键原始证据；共享问题修产品；局部问题留作者选择 | 无未解决科学硬错或版式硬伤；记录人工修正量与剩余科学缺口 |
| 5 有界发布 | 支持平台测试、安装回放、公开合成样例、真实能力说明 | 只发布实测能力；未达主目标则如实报告，不用小功能堆成“已完成” |

执行时主控加两条短支线：A负责科学流程/专属技能与案例评价，B负责首次稿桥接/
专属测试和图文演示；主控独占公共manuscript接口、CLI、版本及集成，避免并行覆盖。
阶段1后才按实际需要启动支线，不建立常驻审查团队。正常实现连续推进，只有实质
科学选择、额外求解、敏感材料或扩大范围才问作者。

## 5. 验收和可证明的改进

1. 作者给材料、粗略目标、必要澄清，不手填机器协议。
2. 引言问题能在结果/讨论及结论中找到回应；新增讨论必须提供证据综合或解释价值，
   不能只变长、换同义词或多写免责声明。由评阅者指出具体段落，不按关键词打分。
3. 关键数值、单位、工况和图文引用无已知硬错；所有关键机制主张有相应证据层级。
4. 文献内容和使用角色匹配；未证新颖性、独立验证与因果结论不能自动升级。
5. 实际图、表、公式均入DOCX；逐页可读，作者已有修改不因无关编辑丢失。
6. 记录首次操作中的协议错误/重试、主控救场、人工科学更正、未请求内容改动；
   目标是不再要求主控代写映射胶水或人工修最终文档。未实现就明确列出。
7. 本轮不是默认做又一次大规模A/B。若要声称比v0.13更快或更深，另行固定相同输入、
   宿主配置与预算作配对比较；没有这种证据就只声明实际实现与完成的任务。

## 6. 历史资产与未纳入本版的工作

P04多图与引言/方法/结论演化用于真实科学写作判据，不只复用Fig.5；
散热A–F外审用于壁温定义、机制不足、跨工况比较和格式反例；Gate5用于不可比、
错误趋势、缺证和虚假批准回归。按问题读取原资料，不全量重扫、不改原稿。
已有外部项目研究供架构/技能选用，不再铺一轮泛泛竞品调研或直接覆盖本机技能。

已知项目上新任务仍不是陌生项目；后续至少补一次真正陌生的非燃烧器成熟结果试用，
尤其瞬态/多相目标不因现有两个领域成功而关闭。若当前材料缺重要科学证据，
先缩小可回答问题或向作者列最小补证需求，不擅自求解、不承诺投稿就绪。

原生Fluent/STAR适配、Word批注有限回收、可选模型API执行、真实审稿返修作为后续
按外部任务启动的能力；本版不并行铺开。最终目标仍是专业、好用的半自动SCI工作流，
不是无人工判断的论文工厂。
