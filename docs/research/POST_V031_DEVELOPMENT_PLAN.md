### 后续顺序及停止条件

1. **原表到写作的直接衔接（本次）**：公开命令生成并传递计算结果；验证完整行读取、缺失值、统计定义和可携带来源。计算报告服务科学推理，不新增审批、注册表或用户前台门禁。
2. **成稿尺度下的图文质量**：在现有绘图/文档路径优先解决外部试用出现的实际可读性问题。保留可编辑脚本和图件；选一份真实输出按目标宽度检查，不改数据、不默认重构图型。不要同时建设完整期刊模板平台。
3. **新材料上的宿主辅助小节试用**：使用未提供成稿的新案例或新比较，记录硬错误、有效物理解读、作者实质改写及手工整理输入的工作。看宿主是否能从已有结果选取有价值的诊断并写出自然论证，而非只看禁用词或测试数量。缺少独立素材时明确待试，不反复“盲测”已修好的稿件。
4. **按需要补充场诊断**：某项重要机制确实需要时，再接入指定区域/截面的场提取；先明确量和算子，不为补一项证据扩成通用求解器平台。文献工作区、完整论文、自审与真实返修仍保留在后续路线，不因当前局部测试提前宣布完成。

每次外部反馈按“完整意见 → 实际原因 → 最小能力改动 → 通用测试和真实回放 → 下一次使用表现”推进。产品证据分开报告：**案例修订、已接入产品的能力、仍靠宿主判断的工作、尚未验证的功能**。已经通过且未变化的检查不重做；发现科学解释问题不靠增加审计文档掩盖。

P04 的成功图文与写作演化继续作为深度和表达的正向参照；旧 Gate 5 的错误比较/趋势作为负向参照；本次跨领域试用检验传热语义与可用性。私有数值、原图及项目路径不写入公开测试；公开测试使用小型合成数据。资源比例保持 **55% 科学分析、25% 绘图写作、10% 易用性、10% 必要可靠性**。

## 3. 推荐 v0.4.0：从单图科学论证到多证据小节

### 用户成果

首先输入一张关键图、对应数据、比较定义与必要方法背景，生成能够解释主要现象的结果与讨论文本。图可以包含多个场或指标面板，段落数量服从论证需要。随后在同一项目中组织多组相关结果，形成连贯小节。2–3组证据、约500–800词仅供容量设计参考，不作为成果配额；一张图写得充分比凑够图数更重要。用户可以修改图件或文字后继续工作。

### 科学与写作行为

1. 从已导入记录读取 case、变量、单位、比较和来源；提出可用的分析组合与候选小节职责。只问无法可靠识别、且影响解释的少量关键问题。
2. 支持多组分析同时存在，按分析标识关联图件与段落，避免后来一次分析覆盖之前的结果。沿用当前存储与契约，确需增加字段时由主控统一确定。
3. 小节结构按“问题与比较目的—可见结果—定量支持—物理解读—意义”组织；不强制每段重复全部步骤，不机械拼接现有模板段。
4. 区分观察事实、候选机理和已有证据支持的解释。现有验证数据的适用范围要与具体主张匹配；验证缺失不等于所有物理讨论都必须删除，推测也不能写成验证结论。
5. 宿主 AI 或已有 provider 可提出段落与措辞，计算及图件读数由现有分析产物提供。离线保留结构与事实稿，明确它与经模型编辑的小节的质量差异。
6. 作者已提供的文献可以与论断及原文位置关联；本版不建设自动文献搜索系统。缺少机理证据时指出具体需求，不补造引用。
7. 图件复用统一样式配置，保证同一变量/case 的视觉语义一致，保留源数据与可运行脚本，提供 SVG/PNG/PDF/TIFF。首先保留独立图件，组合多面板仅在该小节确有需要时加入。
8. 编辑后可局部更新；同一处来源变化只使相关产物需要重做。保留作者图件和文字修改，发生覆盖冲突时展示差异。

### 单图深度写作的具体要求

- 先识别图件角色：几何/概念、方法/采样、数值可信度、场观察或指标综合。不同角色采用不同读法，不统一套用“Fig. X shows”加趋势罗列。
- 对核心结果图建立论证职责：比较目的、可见变化、最少且足够的定量锚点、解释、文献角色与科学意义。职责可以跨段分配，简单图可合并，不强制固定句序或固定数量的数字。
- 用与问题相关的守恒、输运、源项、特征尺度或无量纲关系解释变化。只有输入支持时才展开公式或量级估算；不能用泛泛的“耦合增强”替代具体物理过程。
- 核查几何、边界、模型、负荷等同时变化的因素，区分构型比较与操作参数比较。联合变化可以讨论，但不能包装成已分离的单因素因果效应。
- 对照不同诊断量：方向一致时说明彼此支持的环节；不一致时判断是否来自采样范围、归一化、局部/总体差别或竞争机制。数据冲突不能通过删除不方便的指标消失。
- 对候选机理说明它能解释哪项观察、仍缺哪项判别证据。若已有证据无法区分两个合理解释，提出最低补充分析需求；不自行补算或把猜测写成已证实。
- 文献分别承担背景、方法、机理或比较角色。全文适用范围与本项目差异必须核实；必要限定放在合适位置，不在每段重复防御句。

### 已有云图和图件的入口

作者提供的现有图像可以与相关标量数据一起使用，暂不要求先完成通用场分析。输入需能对应case、面板、变量、单位、截面/时刻及色棒含义；Agent先从文件与已有记录识别，只询问影响解释的缺项。

有图像能力的宿主读取实际图件；没有图像能力时使用明确标为作者观察的描述，并报告尚未完成图像核对。不能把阅读caption或证据表称为已目检图件，不能由颜色估造精确值。区分显示量、派生定量指标和物理推断，例如cell-integrated源项与体积源项、局部组分与总体性能。

旧图导入与新图生成分别处理：旧图保留原貌和作者精修；新图按源数据与图件方案生成。不为写作方便擅自重绘、补inset、平滑或改变色棒。真实字段/单位存在疑问时局部停用相关定量论断，其余有证据的观察仍可写。

### 最小交付

- 小节提纲：每段负责什么、引用哪张图、支撑哪个主张。
- 一项关键图的深入论证，以及一个多证据小节示例；相关分析、编号、图注和源数据一致。
- 可编辑小节文本与一个实际嵌入图件、图注的小节 DOCX。
- 论断到数值/观察/文献位置的后台关联记录。
- 自包含外部 AI 审查包与意见导入；作者可以接受、部分接受或拒绝建议。

这里的 DOCX 是小节预览交付，使用单一简洁模板。全稿装配、复杂 Word 对象无损处理、通用 export 和投稿排版仍属于后续版本。

## 4. Skill 如何实际起作用

扩展现有四个 Skill，使用同一 CLI/项目产物。入口从用户任务识别主 Skill，并只加载需要的参考、模板和脚本。

- intake：读取已有图、数据与方法记录，区分图像读取和作者提供的观察，再询问影响解释的缺项。
- QoI：提出相关比较和诊断量，检查采样、归一化、同时变化因素与诊断间的支持或冲突。
- figure：围绕科学问题组织证据，说明显示量；新图复用样式，旧图尊重作者本地精修。
- writing：落实单图论证职责，解释具体物理过程、竞争机理及文献作用，再扩展到小节衔接与作者修改。

用一次基线与一次加入项目专用指导后的同输入回放比较实质修正需求和重复错误。本次基线实际用了通用 scientific-writing Skill，不能称为无 Skill 对照；改进轮保留该通用指导并记录新增指导。当前版本先验证本地 CLI 加一个实际可用 AI 宿主；其他宿主随后按真实需求验证。文献与投稿审查 Skill 随对应能力开发，不先填充空包。

## 7. 评价、协作与停止点

评价同时检查科学正确性与论证质量。用同一输入、同一宿主模型和相当的上下文预算比较基线指导与改进指导，各执行一次；先保存初稿再统一审阅，明确实际加载的Skill。当前CLI若不能消费某项云图输入，应如实记录不支持，不把手工转写或宿主生成的正文称为旧CLI产物。CLI的数值/图件结果单独核对。

| 评价项 | 满足要求的表现 |
|---|---|
| 图像与事实 | 描述真实可见变化；数字、单位、case、方向、显示量正确；没有虚构panel/inset |
| 比较与归因 | 比较对象清楚，同时变化因素处理恰当，没有把相关性写成已分离因果 |
| 物理深度 | 具体解释输运/源项/尺度关系；有证据时处理竞争机制或诊断冲突；不靠术语数量显得深入 |
| 文献作用 | 给定文献内容确实支撑对应句，适用范围清楚，引用不能替代本项目结果 |
| 组织与语言 | 关键现象得到解释、数字有取舍、段落衔接自然，caption自明且不重复讨论 |
| 人工成本 | 记录需要补充的关键事实、实质重写位置和作者修改量；不虚报尚未测量的耗时 |

判定新版改进需满足：没有关键科学硬错误；在原有不足的读图、机理或组织方面有可指出的实质改善；未增加作者补资料与重写负担。单次回放只提供该案例的证据，不宣称统计显著或普适。评价参照包括批准稿和修正记录，但不要求复刻其措辞。若初稿不合格，围绕具体原因修正并做一次定向回放；仍无提升则先报告原因，不无限打磨。

写作阶段的外部审查包包含实际图像、相关数据、比较与单位定义、候选稿和必要文献内容；外部模型无法渲染图像时明确留下这部分待核，不把文字审查冒充视觉审查。有价值意见经作者判断吸收；本轮不用新建评分平台或增加常驻审批对象。

科学分析、多产物存储、图文写作可分配给边界清楚的执行任务，主控统一公共接口并整合。实际任务数随批次决定，不预设大量并行进程。每批次一次聚焦测试和简明汇报；只有新错误或实际冲突才扩大复查。
