### 科学产出仍存在的不足

1. 真实试用的科学问题、方法摘录和图件由主控预先组织；尚未证明宿主可以低救场成本地
   从较普通的资料包完成这些选择。不能把一次主控准备好的成功小节当作自动发现能力。
2. v0.17主要写材料温差/交互作用，单芯时序只做计算回归；尚未完成事件、温度状态、
   峰值与模型角色之间的联合论文论证，也未充分利用反对单指标结论的证据。
3. 首稿数值密度偏高，部分重复边界解释进入正文；没有文献对话或明确的相邻章节传播试用。
4. 教学三面板是针对固定数据的脚本，不是已产品化的通用多证据绘图能力；不能把新增一张
   好看的示例图算成一般用户也会得到这种效果。
5. v0.16散热首稿仍有已知几何/导热参数遗漏、归一化算子定义不足、参考归属不完整。
   携带更多资料不自动保证方法可复现或讨论更深。

## 2. v0.18目标和边界

**主目标：让宿主从已有资料选出判别性观测，形成多观测一致或冲突的科学解释，
并把这一主线写进连贯Methods—Results—Discussion及短结论，而不是再交一段孤立结果清单。**

可验收的用户收益：默认绘图与正文同口径；参考范围可复算；多面板图真正显示决定论断的
证据；方法保留决定解释的已知参数；讨论具体回应为何相同模型会在不同观测上表现不同。
模型未整体吻合不等于停止写作：有足够证据时可形成有价值的诊断研究，不能只交缺口清单。

不做：新仿真/重新拟合、全套原生求解器适配、新provider SDK集群、Word无损同步平台、
自动投稿、一般因果发现、任意加权成熟度评分、专门审批/哈希/注册表体系。
复杂机制示意沿用已集成的外部工具任务，不自研画布；本轮图件开发是有限数值图型。

## 4. 五项实施任务

### T1：修复默认分析—绘图断点（首先完成）

- 补齐时序参数转发与标签；让图件计算、写作包与正文绑定使用同一声明。
- 用小型共享调用函数或明确一致转发解决真实的多调用点漂移，不建通用插件平台。
- 增加实际plot入口测试：精确窗口、累计量、采样阈值、缺失事件以及相容/不相容比较。
  断言图源表与正文绑定相同，不仅检查图文件生成成功。
- 没有事件/不足以绘图时给出具体缺口或采用既有prose/table，不产生伪数据。

### T2：可复算的参考范围对照与联合科学读法

- 先复用scalar_select、paired_change、temporal和result_comparisons做可做的比较。
- 对确实缺少的参考范围运算补一个有限helper/operation：保留模型值、参考中心/上下界，
  计算有符号偏差和超出范围距离；原表已有error/within字段作为核对，不能当唯一计算来源。
- 参考单位、观测量/位置/时段与范围含义由来源建立；绝对温度差报告K，缺失界限保持缺失。
- “范围内”只描述该观测，不产生模型总体通过状态；事件与温度不可拼成混单位总误差。
- 在已有科学上下文中标明各证据回答的问题、对解释的支持/反对作用和具体补证需求。
  只补真实必要字段；不另造claim评分库，不用机械关键词判机制正确。

### T3：把有限多证据图型接入产品

- 首批仅支持需要的时序profile和模型—参考区间/残差两种数值panel；组合成互补多面板。
  构图由科学问题决定；没有原始时间曲线或比较定义时不伪画profile。
- 复用现有figure_plan/外部图件包和v0.17的版心/字体处理，不为一张图建新绘图框架。
- 图中的温度、时间、区间与残差保持独立且明确的量纲；区间图不伪装统计误差棒。
- 新图源表、代码和正文共用所选定义；可编辑SVG/PDF、PNG/TIFF和本地脚本同时交付。
  图型/坐标/配色参数可供作者精修，不能覆盖其已有局部脚本。
- 分组marker/颜色、统一字号/图例、克制网格、Linux字体回退和Word实际版心检查均沿用。
  看得出关键差异而不改变读数；不靠更多panel或装饰增加信息量。

### T4：科研首稿与跨章节论证

- 更新科学分析/绘图/写作专用技能；能力改动必须在实际宿主任务中用到。
- 从来源中优先读取影响当前解释的几何、物性、源项、边界、数值和观测定义；
  不能为避免遗漏把全部配置逐项复制进Methods，也不能让作者预填全套问卷。
- 同一问题贯穿Methods、Results、Discussion和短结论；已有manuscript/spine/跨章绑定复用。
  一处定义、适量定量锚点，解释冲突与可区分假设，不把审计/日志记录写成论文。
- 将原始已核验文献段落用于实际模型/观测比较，说明具体相同点、差异与推论；
  不按标题或DOI猜支持。资料缺失时留下具体文献任务，不补造论据或新颖性。
- 主试用至少交一个有相邻章节的研究片段及真实图文，不以完整摘要/整篇论文凑齐目录。
  所需篇幅服务科学问题，不把多写字或限制声明当深度指标。

### T5：一次有界试用、收口与发行

- 先保存首次任务/输出，再作一次集中评阅；最多一次反馈修订，首稿不覆盖。
- 相同新任务优先用实际安装v0.17与v0.18候选的隔离宿主首次输出比较；
  输入、题目和提供的科学信息相同，新版本指导可以不同。没有对照则不宣称提升。
- 评价重点：硬数值、必要方法覆盖、多观测选择、解释的区分力、文献角色、重复防御、
  实际图文可读性、主控补映射/修协议/科学救场次数。数值项复算，论证由读稿判断。
- 新稿若只多了边界句而没有科学收益，不能宣称高质量写作升级；优先修造成遗漏的入口，
  保留局部成功/失败，不无限改prompt直到评价看起来通过。
- 跨供应商试用采用已有无答案任务包，有可用宿主时执行并记录实际版本/能力。
  没有账号/访问条件时交付包和未测状态，不阻塞确定性核心，也不冒充已兼容验证。
- 相关测试、一次最终全量回归、Windows/Linux CI及发行包安装；实际Word/PDF逐页检查。
  无源/代码/环境变更的旧验证复用，不在每个小批次重复全量测试或提交审查。

## 5. 分工和执行顺序

采用主控+两条短支线，实施时分配，不在规划阶段新开任务。

- 主控：冻结本轮问题/最小接口、写作技能与宿主包、真实试用、科学评阅与最终整合发行。
- 科学支线：参考范围计算及单位/观测定义；table_evidence等限定文件与针对性测试。
- 图文支线：默认绘图接线、有限多panel输出和Word尺寸适配，限定渲染文件/测试。
- 若一个新helper需改共享调用/section声明，由主控独占或预先明确所有权，不同时编辑。
  首次生成/评阅在独立上下文中执行，只给相应材料；不设常驻审计队列。

顺序：T1修复 → 主试用资料/问题选择 → T2与T3并行 → T4连贯首稿 → T5一次评阅/发行。
沿用现有三个人工科学决策点：研究问题、证据/图件、最终稿；不增加软件形式门禁。
本计划确认后常规实施持续推进，不为每个子任务重复索取批准。

## 6. 可交付验收及后续边界

1. 自动绘图与正文在相同定义/窗口上读数一致，包含实际失败路径的修复回归。
2. 所选参考差异由原值复算；印刷范围、图读包络、模型对照和实验验证不混淆。
3. 图展示决定论断的互补观测，所有主读数在最终Word尺寸可读；输出可编辑、可复绘。
4. 方法足以理解当前比较，Discussion不遗漏相反证据，且有来源支持的具体物理解读。
   能说清哪些假设被支持/反对、哪一个现有证据能区分替代解释，而不是只说需要更多研究。
5. 参数、QoI和研究结论跨章节传播一致；实际首次作品与修改后作品分别保存。
6. 至少一次新任务首稿和一次非电池定向回归；不能把两个模型、三个领域名字当作通用性通过。
   若首稿无稳定质量增益，发布说明按实际实现限缩，不给成熟可投稿认证。

更广原生提取、一般瞬态/多相验证、Word手工修改回收、真实返修和多供应商独立使用仍保留，
但不全塞进v0.18。下轮优先级由实际科研使用反馈决定，而非再堆版本功能数。
